# 営業秘密AIチェック

## 背景

AIサービスへの情報入力は、営業秘密の3要件のうち特に「秘密管理性」と
「非公知性」に影響を与える可能性があります。不正競争防止法第2条第6項の
営業秘密としての保護を維持するため、AI利用における秘密情報の取扱いを
評価します。

## 営業秘密の3要件

| 要件 | 定義 | AI利用での懸念 |
|------|------|----------------|
| 秘密管理性 | 秘密として管理されていること | AIサービスへの入力は「管理の放棄」とみなされるか |
| 有用性 | 事業活動に有用な情報であること | 通常、AI利用場面では充足 |
| 非公知性 | 公然と知られていないこと | AIサービス経由で情報が学習・流出するリスク |

## 評価フロー

### ステップ1: 情報の特定と分類

確認事項：
1. **入力する情報の内容**: 具体的にどのような情報をAIに入力するか
2. **営業秘密該当性**: その情報は営業秘密として管理されているか
3. **秘密管理の実態**: アクセス制限、秘密表示、管理規程の有無
4. **情報のレベル**: 極秘 / 社外秘 / 関係者限り / 公開情報

### ステップ2: AIサービスの利用態様の確認

| 確認項目 | 内容 |
|----------|------|
| AIサービスの種類 | クラウドAPI / SaaS / オンプレミス / エッジ |
| データの取扱い | 入力データは学習に利用されるか |
| データの保存 | 入力データの保存期間・削除ポリシー |
| 第三者アクセス | ベンダーの従業員が入力データにアクセスできるか |
| サーバー所在地 | データが保存されるサーバーの所在国 |
| 契約上の保護 | 秘密保持条項、データ処理契約の有無 |
| オプトアウト | AI学習へのデータ利用のオプトアウト設定の有無 |

### ステップ3: 3要件への影響分析

#### 秘密管理性への影響

| リスクシナリオ | 影響 | 対応策 |
|---------------|------|--------|
| クラウドAIに秘密情報を入力（学習利用あり） | 秘密管理性の喪失リスク高 | 学習利用オプトアウト、契約上の秘密保持 |
| クラウドAIに秘密情報を入力（学習利用なし、契約あり） | リスク低減 | 契約内容の確認、技術的措置の確認 |
| オンプレミスAIで処理 | リスク低 | アクセス管理の維持 |
| API利用（データ保存なし） | リスク低〜中 | 一時的な処理であることの確認 |

#### 非公知性への影響

| リスクシナリオ | 影響 | 対応策 |
|---------------|------|--------|
| 入力データがモデル学習に利用される | 非公知性の喪失リスク | オプトアウト設定、別手段の検討 |
| 他ユーザーへの出力に反映される可能性 | 非公知性の喪失リスク | ベンダーのデータ分離体制の確認 |
| プロンプトインジェクション攻撃 | 漏洩リスク | 入力情報の限定、セキュリティ対策 |

### ステップ4: リスク評価と推奨事項

リスクレベルの判定：

| レベル | 定義 | 対応 |
|--------|------|------|
| 高リスク | 営業秘密性の喪失が現実的に懸念される | AI利用の中止または大幅な対策が必要 |
| 中リスク | 適切な対策により管理可能 | 条件付きで利用可、対策の実施を条件 |
| 低リスク | 営業秘密性への影響は限定的 | 基本的な注意事項の遵守で利用可 |

## 失敗モード（避けるべきこと）

- 営業秘密性の喪失を安易に否定しない — 裁判例は厳格に判断する傾向
- 契約上の秘密保持条項があれば安全と断言しない — 技術的措置も重要
- オプトアウト設定の有無だけで判断しない — 実効性の確認が必要
- 海外サーバーへのデータ送信リスクを見落とさない
