# AI影響評価（AIA）

## 処理フロー

1. 設定ファイルの読み取り
2. リスクトラック（簡易/標準）の判定
3. インテーク（情報収集）
4. 7原則に基づくリスク分析
5. 適用法令ごとの規制分類
6. 評価書の作成
7. ポリシー整合性チェック
8. 出力（条件・ハンドオフ付き）

## マターコンテキスト

マターワークスペースが有効な場合、出力をマターフォルダに保存。

## ステップ0: 影響評価の要否

プロファイルのトリガー基準を確認：
- Tier 2以上のユースケース → 必要
- 新規AIシステムの導入 → 必要
- 既存システムの大幅変更 → 必要
- Tier 1かつ変更なし → 不要（根拠を記録）

## ステップ1: リスクトラック判定

| トラック | 条件 | 対応 |
|----------|------|------|
| 簡易 | Tier 2・低複雑度・単一法域 | 短縮版テンプレート |
| 標準 | Tier 3以上・高複雑度・クロスボーダー | 完全版テンプレート |

出典の信頼度タグ：
- `[確定]` — 法令の条文、確立された解釈
- `[要確認]` — ガイドラインの解釈、実務上の判断
- `[要確認・要出典]` — 判例・学説の引用が必要

## ステップ2: インテーク

会話形式で以下を収集：

1. **システム概要**: 何をするAIか、目的は何か
2. **影響を受ける人**: 誰が影響を受けるか、規模はどの程度か
3. **入力データ**: どのようなデータを使用するか、個人情報を含むか
4. **判断と監視**: AIが行う判断、人間の監視体制
5. **精度と障害**: 精度要件、誤りが生じた場合の影響
6. **展開段階と規模**: PoC / パイロット / 本番、利用者数

## ステップ3: 7原則に基づくリスク分析

AI事業者ガイドラインの7原則ごとにリスクを評価：

| 原則 | 評価観点 | リスク評価 |
|------|----------|-----------|
| 人間中心 | 人間の尊厳、自律性、人権への影響 | 高/中/低/該当なし |
| 安全性 | システム障害リスク、品質管理体制 | 同上 |
| 公平性 | バイアスリスク、差別的結果の可能性 | 同上 |
| プライバシー保護 | 個人情報の取扱い、データ最小化 | 同上 |
| セキュリティ確保 | サイバー攻撃リスク、データ漏洩リスク | 同上 |
| 透明性 | AI利用の開示状況、説明可能性 | 同上 |
| アカウンタビリティ | 責任体制、苦情対応、監査可能性 | 同上 |

リスクの記述品質基準：
- 具体的なリスクを設計に紐付けて記述する
- 「AIの誤り」のような汎用的な記述は不可
- 「このモデルが○○データで学習されているため、△△の場面で□□のバイアスが生じうる」のように具体化

## ステップ4: 適用法令ごとの規制分類

プロファイルの規制フットプリントに基づき、法令ごとに確認：

| 法令 | 確認事項 |
|------|----------|
| AI事業者ガイドライン | 役割（開発者/提供者/利用者）ごとの対応事項 |
| 著作権法 | 第30条の4の適用可否、享受目的の有無 |
| 個人情報保護法 | 個人情報の取得・利用・第三者提供の適法性 |
| 不正競争防止法 | 営業秘密のAIへの入力リスク |
| 業種別規制 | 金融・医療・通信等の業種固有の要件 |

## ポリシー整合性チェック

自社AIポリシーと照合し、以下を確認：
- ユースケースがポリシーの許可範囲内か
- 必須セーフガードが充足されているか
- 開示義務に対応しているか
- ベンダーが承認リストに含まれているか
- 不整合がある場合は一つずつフラグ
