# /auto-updater

1. `~/.claude/plugins/config/claude-for-legal/legal-builder-hub-jp/CLAUDE.md` → インストール済みスキル + 更新設定を読み込む。
2. 以下のワークフローに従う。
3. 各インストール済みスキルのソースで新バージョンを確認する。
4. 設定に応じて：適用 / 通知 / 差分表示。

---

## 目的

コミュニティスキルは改善される。本スキルは更新を検出し、変更内容を表示し、
明示的な承認後にのみ更新を適用する。

## 信頼姿勢

インストール済みスキルは法務環境内で実行されるコードである。上流リポジトリの
侵害、所有者の変更、意図しない動作変更の可能性がある。**いかなる更新も、差分を
読み承認するまで適用されない。** これは設計である。

## 読み込むコンテキスト

`~/.claude/plugins/config/claude-for-legal/legal-builder-hub-jp/CLAUDE.md` → インストール済みスキル（バージョン/コミット SHA 付き）、更新設定（notify / manual）。

## ワークフロー

### ステップ 1: 各インストール済みスキルの確認

各スキルについて：

- ソースレジストリから現在のコミット SHA を取得する（タグやブランチヘッドではなく正確なコミット — タグは可変でありパブリッシャーにより遡及的に書き換え可能、コミット SHA のみが不変）
- インストール時に固定された SHA と比較する
- 差異がある場合：更新あり

### ステップ 2: 差分と信頼レビュー

各更新について、完全な差分を表示する：

```diff
# [スキル名] — [インストール済み SHA] → [最新 SHA]

## SKILL.md の変更
[unified diff]

## hooks/hooks.json の変更
[unified diff — フラグ: hooks は任意のコードを実行可能]

## .mcp.json の変更
[unified diff — フラグ: MCP サーバーはユーザーの認証情報で実行される]

## その他のファイル
[追加/削除/変更されたファイルの一覧と差分]
```

信頼チェックを実行する：
- **`hooks/hooks.json` が変更されたか？** 目立つように表示し、新しい hooks の内容を確認させる。
- **`.mcp.json` が変更されたか？** 同様に扱う。
- **`allowed-tools` / `tools` が拡張されたか？** 権限昇格として扱う。
- **新たなネットワーク呼び出し、スキルディレクトリ外へのファイル書き込み、コマンド実行がないか？** フラグ付け。
- **スキルの `description` や目的が変更されたか？** 目的の変更はスキルの転用を意味しうる。

### ステップ 2.5: 新バージョンの再スキャン（GlassWorm ゲート）

更新適用前に、新バージョンに対して以下の検証を実行する：

1. `/legal-builder-hub-jp:bengoshi-ho-guardrail` を新バージョンに対して実行
2. `/legal-builder-hub-jp:japanese-law-validator` を新バージョンに対して実行
3. `/legal-builder-hub-jp:skills-qa` の完全スキャンを新バージョンに対して実行

**ルール:**

1. **退行時はフェイルクローズ。** 新バージョンが旧バージョンになかった所見を出す場合、デフォルトで更新を拒否し理由を説明する。
2. **セキュリティ面の差分は判定に関わらず人間の承認を要する。** `hooks/hooks.json`、`.mcp.json`、`allowed-tools`/`tools`、新規 Bash/WebFetch/WebSearch、新規外部 URL、スキルディレクトリ外への書き込み、`description` の変更は、クリーンなスキャン結果でも人間の承認を必須とする。
3. **弁護士法第72条ゲートの退行は更新をブロックする。** 旧バージョンで実装されていたゲートが新バージョンで削除・弱体化されている場合、これを明示的に警告し、デフォルトで更新を拒否する。
4. **「拒否」判定は上書き不可。** skills-qa が拒否判定を出した場合、「それでも適用」オプションを提示しない。

### ステップ 2.6: 法改正に伴う更新の優先度判定

法改正に関連する更新を検出し、優先度を判定する：

**高優先度（即座に対応推奨）:**
- スキルが依拠する法令の改正に対応する更新
- 施行日が迫っている法改正への対応
- 既知の誤り（条文番号の誤引用等）の修正

**中優先度（計画的に対応）:**
- 新しい判例や行政解釈への対応
- 法令用語の更新（例：「瑕疵」→「契約不適合」）

**低優先度（任意）:**
- ドキュメントやフォーマットの改善
- 機能追加

優先度は更新ログに表示し、ユーザーが重要な更新を先に対応できるようにする。

### ステップ 2.7: 鮮度トリガーの再検証

新コミットの有無だけでなく、インストール済みスキルが鮮度ウィンドウを経過していないかも確認する。

インストールログから検証済みの `last_verified`、`freshness_window`、`freshness_category` を読み取る（ライブの SKILL.md フロントマターからではなく — 侵害された更新がフロントマターを上書きして偽の鮮度を主張する可能性がある）。

鮮度ウィンドウ経過時は選択肢を提示する：
- (a) `verified_against` URL を自身で確認する
- (b) レジストリメンテナーにフラグを立てる
- (c) 再検証まで無効化する

### ステップ 3: 設定に応じた処理

**notify（デフォルト）:** 完全な差分と信頼チェックを表示。「更新が利用可能です。上の差分を確認してください。適用しますか？ [はい/いいえ]」

**manual:** 更新のあるスキル一覧のみ表示。ユーザーが準備できた時に `/legal-builder-hub-jp:auto-updater --apply [スキル名]` を実行。

「auto」モードは存在しない。法務環境で実行されるコードの更新には、常に人間が差分を読むことを要する。

### ステップ 4: 適用（明示的な承認後）

インストール済みスキルファイルを新バージョンで置換する。`~/.claude/plugins/config/claude-for-legal/legal-builder-hub-jp/CLAUDE.md` のインストール済みリストを新コミット SHA で更新する。ロールバックに備えて旧バージョンをバックアップする（`~/.claude/skills/.backups/[スキル名]-[旧SHA]/`）。

### 更新ログの表示

更新履歴を時系列で表示する：

```
## 更新ログ — [日付]

| スキル | 旧SHA | 新SHA | 優先度 | 変更概要 | 検証結果 |
|---|---|---|---|---|---|
| [名前] | [SHA] | [SHA] | [高/中/低] | [一行の概要] | [利用可/一部懸念/…] |
```

## ロールバック

更新で問題が発生した場合：`/legal-builder-hub-jp:auto-updater --rollback [スキル名]` でバックアップから復元する。

## 本スキルが行わないこと

- 自動適用。絶対に。すべての更新に差分表示と承認を要する。
- ハブ経由でインストールされていないスキルの更新（手動配置スキルはユーザー自身が管理する）。
- タグ、ブランチ、バージョン番号を信頼する。コミット SHA のみを固定する — コミット SHA のみが不変であるため。
