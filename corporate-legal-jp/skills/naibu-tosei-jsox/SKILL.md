# /naibu-tosei-jsox（内部統制・J-SOX）

1. `~/.claude/plugins/config/claude-for-legal/corporate-legal-jp/CLAUDE.md` → `## 上場会社`及び`## 組織情報`を読み込む。
2. 以下のワークフローに従い、内部統制の整備・運用状況の確認を支援。

---

## コンテキストの読み込み

- `~/.claude/plugins/config/claude-for-legal/corporate-legal-jp/CLAUDE.md` → `## 上場会社`（上場市場、事業年度末等）
- `~/.claude/plugins/config/claude-for-legal/corporate-legal-jp/CLAUDE.md` → `## 組織情報`（ガバナンスモデル、法人形態等）

上場会社でない場合: 会社法上の内部統制のみ対応し、J-SOX（金商法）部分はスキップ。

---

## 目的

内部統制は、会社法と金融商品取引法の二つの法的枠組みで要求される。本スキルは、法務部門の観点から内部統制の整備・運用状況を確認し、法的要件の充足を支援する。

---

## Step 1: 法的枠組みの確認

### 会社法上の内部統制（大会社・上場会社）

**会社法第362条第4項第6号（取締役会設置会社の場合）:**

取締役会は、以下の体制の整備を決定しなければならない:
- 取締役の職務の執行が法令及び定款に適合することを確保するための体制
- 取締役の職務の執行に係る情報の保存及び管理に関する体制
- 損失の危険の管理に関する規程その他の体制
- 取締役の職務の執行が効率的に行われることを確保するための体制
- 使用人の職務の執行が法令及び定款に適合することを確保するための体制
- 当該株式会社並びにその親会社及び子会社から成る企業集団における業務の適正を確保するための体制

**会社法施行規則第100条** — 上記の具体的内容を規定。

```
□ 内部統制システムの基本方針が取締役会で決議されているか
□ 基本方針の内容が施行規則第100条の要件を満たしているか
□ 事業報告に基本方針の概要と運用状況が記載されているか（施行規則第118条第2号）
□ 監査役（会）の監査報告に内部統制の相当性についての意見があるか
```

### 金融商品取引法上の内部統制（J-SOX）— 上場会社のみ

**金融商品取引法第24条の4の4:**
- 上場会社は、事業年度ごとに**内部統制報告書**を内閣総理大臣に提出しなければならない
- 内部統制報告書は、財務報告に係る内部統制の有効性の評価結果を記載
- **監査法人による内部統制監査**が義務（金商法第193条の2第2項）

## Step 2: 内部統制の4つの目的

企業会計審議会「財務報告に係る内部統制の評価及び監査の基準」に基づく:

1. **業務の有効性及び効率性** — 事業活動の目的の達成のため、業務の有効性及び効率性を高めること
2. **報告の信頼性** — 財務報告及びその他の報告の信頼性を確保すること
3. **事業活動に関わる法令等の遵守** — 事業活動に関わる法令その他の規範の遵守を促進すること
4. **資産の保全** — 資産の取得、使用及び処分が正当な手続及び承認の下に行われるよう、資産の保全を図ること

---

## Step 3: 内部統制の6つの基本的要素

各要素の整備状況を確認:

### (1) 統制環境

```
□ 経営者の誠実性及び倫理観が組織全体に浸透しているか
□ 経営方針・経営戦略が明確か
□ 取締役会・監査役の機能が有効か
□ 組織構造・権限と職責が明確か
□ 人的資源に関する方針と管理が適切か
```

### (2) リスクの評価と対応

```
□ リスクの識別・分析・評価のプロセスが整備されているか
□ 不正リスクの評価が行われているか
□ 事業環境の変化に応じたリスク評価の更新がなされているか
```

### (3) 統制活動

```
□ 職務の分掌が適切に行われているか
□ 承認・権限の体系が明確か
□ 資産の管理・記録が適切か
□ ITを利用した統制活動が整備されているか
```

### (4) 情報と伝達

```
□ 経営者に適時に情報が伝達される体制があるか
□ 内部通報制度が整備されているか
□ 外部への情報開示が適切に行われているか
```

### (5) モニタリング

```
□ 日常的モニタリング（業務プロセスに組み込まれた統制）が機能しているか
□ 独立的評価（内部監査等）が定期的に実施されているか
□ 発見された不備が適時に報告・是正されているか
```

### (6) ITへの対応

```
□ IT環境への対応が適切か（ITの利用と制御）
□ IT全般統制（システムの開発・保守、セキュリティ管理、運用管理）が整備されているか
□ IT業務処理統制（個別のアプリケーションにおける統制）が有効か
```

## Step 4: 財務報告に係る内部統制の評価（J-SOX）

### 全社的な内部統制の評価

全社的な内部統制は、企業集団全体に広く影響を及ぼす統制:

```
□ 42項目の評価項目（実施基準の評価項目例）に基づく評価が実施されているか
□ 連結子会社・関連会社を含む評価範囲が適切か
□ 重要な事業拠点の選定基準が明確か
```

**重要な事業拠点の選定:**
- 売上高等の重要な事業活動に係る指標の一定割合（例: 概ね2/3）をカバーする拠点を選定
- 質的重要性のある拠点（リスクの高い事業を行う拠点等）も追加で選定

### 業務プロセスに係る内部統制の評価

```
□ 重要な事業拠点における重要な勘定科目に至る業務プロセスが識別されているか
□ 3点セット（フローチャート、業務記述書、リスクコントロールマトリクス）が整備されているか
□ キーコントロールが識別され、運用テストが実施されているか
□ サンプリング（25件/統制活動が実務上の目安）が適切に行われているか
```

**評価対象となる主要な業務プロセス:**
- 売上プロセス（受注→出荷→売上計上→回収）
- 購買プロセス（発注→検収→買掛計上→支払）
- 在庫管理プロセス
- 固定資産管理プロセス
- 決算・財務報告プロセス
- その他重要なプロセス（見積り、引当金等）

## Step 5: 不備の識別と是正

### 不備の分類

**不備（deficiency）:**
- 内部統制が存在しない、又は規定どおりに運用されていない、又は整備されているが運用が有効でない状態

**重要な不備（significant deficiency）:**
- 財務報告の重要な事項に虚偽記載が発生する可能性が高い内部統制の不備

**開示すべき重要な不備（material weakness）:**
- 財務報告に重要な影響を及ぼす可能性が高い内部統制の不備
- 金額的重要性: 連結税前利益の概ね**5%**が目安
- 質的重要性: 上場廃止基準、財務制限条項への抵触等

```
□ 発見された不備が適切に分類されているか
□ 開示すべき重要な不備に該当する可能性のある不備がないか
□ 不備に対する是正計画が策定されているか
□ 是正状況の追跡が行われているか
□ 期末日までに是正が完了しているか
```

### 是正計画の要素

```
不備の内容: [具体的な不備の内容]
影響を受ける勘定科目: [売上高、売掛金等]
影響の金額的重要性: [推定影響額]
是正措置: [具体的な是正措置]
担当者: [是正の担当者]
完了予定日: [是正完了予定日]
ステータス: [未着手 / 進行中 / 完了 / テスト中]
```

## Step 6: 内部統制報告書のドラフト支援

内部統制報告書の主要な記載事項:

```
□ 財務報告に係る内部統制の基本的枠組みに関する事項
  - 代表者・最高財務責任者の記名
  - 評価の基準日
□ 評価の範囲、基準日、評価手続に関する事項
  - 全社的な内部統制の評価範囲
  - 業務プロセスに係る内部統制の評価範囲
  - 評価手続の概要
□ 評価結果に関する事項
  - 財務報告に係る内部統制は有効である旨（又は開示すべき重要な不備がある旨）
□ 付記事項
□ 特記事項
```

## Step 7: 出力

1. **内部統制評価レポート** — 評価結果のサマリー
2. **不備一覧と是正計画**（不備がある場合）
3. **レビューチェックリスト:**

```
[成果物ヘッダー — ## 出力設定に基づく]

レビューチェックリスト:
□ 会社法上の内部統制の基本方針が最新か
□ 評価範囲の選定が適切か（重要な事業拠点、重要な勘定科目）
□ 3点セットの整備・更新状況
□ キーコントロールの運用テスト結果
□ 不備の分類が適切か（特に開示すべき重要な不備の判定）
□ 是正計画のステータス
□ 監査法人との協議状況
□ 内部統制報告書の提出期限の確認
```

## 弁護士確認ゲート

**開示すべき重要な不備の判定について:**

> 開示すべき重要な不備の有無は、内部統制報告書の結論に直結し、株式市場への影響、訴訟リスク等を伴う判断です。最終的な判定は経営者が行い、監査法人の監査意見と整合させる必要があります。法務部門としては、不備の分類の法的側面（開示義務、善管注意義務との関係）について弁護士のレビューを推奨します。

## 免責事項

本スキルの出力は法的助言に代わるものではありません。最終的な判断は必ず弁護士にご確認ください。

## このスキルが行わないこと

- 内部統制の有効性に関する最終判断 — 経営者が評価し、監査法人が監査する
- 監査法人による内部統制監査の代替
- IT統制の技術的な実装・テスト — ITチームの領域
- 会計処理の正確性の検証 — 会計・監査の領域
- 3点セット（フローチャート、業務記述書、RCM）の一からの作成 — 現場担当者・内部監査チームとの協働が必要
