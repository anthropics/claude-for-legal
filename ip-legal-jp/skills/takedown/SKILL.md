# /takedown

2つのモード:

- `/ip-legal-jp:takedown --send` — プロバイダ責任制限法に基づく削除要請を起案する。
- `/ip-legal-jp:takedown --respond` — 受領した削除要請をトリアージする。

## 手順

1. **プラクティスプロファイルを読み込む。**
2. **案件ワークスペースを確認。**
3. **モード分岐:**
   - `--send` → 送付モード。権利侵害の特定、プロバイダの特定、削除要請書の起案。
   - `--respond` → 受領モード。受領した削除要請の評価、選択肢提示。
   - フラグなし → 確認。
4. **承認ゲートを遵守。**

## 使用例

```
/ip-legal-jp:takedown --send
/ip-legal-jp:takedown --respond ~/Downloads/sakujo-yousei.pdf
```

## 日本のプロバイダ責任制限法

### 概要

プロバイダ責任制限法（特定電気通信役務提供者の損害賠償責任の制限及び発信者情報の開示に関する法律、2001年制定、2022年改正）は、インターネット上の権利侵害に対するプロバイダの責任と、被害者の救済手続を定める。

### DMCA§512との主な相違点

| DMCA（米国） | プロバイダ責任制限法（日本） |
|---|---|
| Notice-and-takedown（通知即削除） | 送信防止措置の申出（プロバイダに裁量あり） |
| Counter-notice制度あり | カウンターノーティス制度なし（発信者への照会制度あり） |
| フェアユース抗弁 | 限定列挙の制限規定（著作権法第30条〜第50条） |
| §512(f) 虚偽通知の制裁 | 不正な削除要請に対する明示的制裁なし（不法行為法で対応） |
| DMCA agent登録制度 | 対応するエージェント登録制度なし |

### 送信防止措置の申出（送付モード）

**送信防止措置依頼書の構成:**

1. **申出者の表示:** 氏名・住所・連絡先
2. **侵害情報の特定:** URL、投稿日時、投稿内容の特定
3. **侵害されたとする権利:** 商標権、著作権、特許権、営業秘密等
4. **権利が侵害されたとする理由:** 具体的な侵害態様
5. **措置の請求:** 削除（送信防止措置）
6. **資料:** 権利を証する資料（登録証の写し等）

**プロバイダの対応フロー:**
1. プロバイダが発信者に照会（7日間の意見表明期間）
2. 発信者から反論がない場合 → 送信防止措置
3. 発信者から反論がある場合 → プロバイダの裁量判断

### 著作権法上の制限規定

日本にはフェアユースの一般条項がない。削除要請前に、以下の制限規定に該当しないか確認する:

- 第30条（私的使用のための複製）
- 第30条の4（著作物に表現された思想又は感情の享受を目的としない利用）
- 第32条（引用）— 引用の要件: 公表された著作物、公正な慣行に合致、報道・批評・研究等の目的上正当な範囲内
- 第47条の5（電子計算機による情報処理及びその結果の提供に付随する軽微利用等）

## 受領モード

受領した削除要請に対する選択肢:

1. **自主削除:** 侵害が明らかな場合
2. **反論・意見表明:** プロバイダからの照会に対し、非侵害の理由を回答
3. **権利者との直接交渉:** ライセンス取得等
4. **放置:** 7日間の意見表明期間内に反論しない場合、プロバイダが削除する可能性あり

## 弁護士確認ゲート

プロバイダ責任制限法に基づく手続は、法的効果を伴うため弁護士の確認を推奨。発信者情報開示請求を伴う場合は `/ip-legal-jp:sender-info-disclosure` へ連携。

## 免責事項

本スキルの出力は法的助言ではありません。削除要請の送付・対応に関する最終判断は、必ず弁護士にご相談ください。
