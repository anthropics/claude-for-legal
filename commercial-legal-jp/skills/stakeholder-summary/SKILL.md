# /stakeholder-summary

契約レビュー結果を事業部門のステークホルダー向けに要約します。

## 目的

事業部門の担当者は法務メモを求めていない。知りたいのは「署名していいか」「何が問題か」「自分は何をすべきか」の3点。このスキルはレビュー結果をそれに変換する。

## ワークフロー

### ステップ1: 設定の読み込み

`~/.claude/plugins/config/claude-for-legal/commercial-legal-jp/CLAUDE.md` → `## 出力設定` を読み込む。ステークホルダーサマリーの宛先と長さの設定を確認する。未指定の場合のデフォルト：事業部門長宛て、2段落以内、法務用語なし。

### ステップ2: 宛先の確認

異なるステークホルダーには異なるサマリーが必要：

| 宛先 | 関心事 | 不要な情報 |
|---|---|---|
| **調達部門** | 価格、更新条件、承認ルーティング | 責任制限の構造 |
| **事業部門長（予算権者）** | チームが使えるか、故障時の影響、コスト | 損害賠償の範囲 |
| **経理部門** | 総保有コスト、更新時の価格リスク、簿外負債 | 準拠法 |
| **情報システム部門** | データの取扱い、セキュリティ要件、サーバー所在地 | その他すべて |
| **経営層** | レピュテーションリスク、法務がブロッカーか否か | 詳細 |

宛先が不明な場合は確認する。

### ステップ3: サマリーの作成

**結論先行型**で作成する（日本のビジネス文書の慣例）。**ですます調**で記述する。

#### 文字数制限（厳守）

- **結論** 1段落：この契約が何で、署名してよいかどうか
- **注意点** 1段落：後で知ったら驚くこと
- **アクション** 2-3項目のチェックリスト（最大3項目）
- **承認** 1行：誰がいつまでに承認するか

**合計400文字以内。** これ以上書いている場合、ステークホルダーが不要な情報を含めている。

#### フォーマット

```markdown
[秘密保持マーキング --- 出力設定に基づく]
<!-- 法務部門外（事業部門、相手方、ベンダー等）に転送する場合は上記マーキングを削除してください。 -->

**[相手方名] [契約類型]** --- [署名可能 | 修正必要 | 保留]

[1段落：この契約が何をするか、ビジネスの言葉で。「クラウドサービス利用契約書に
基づくSaaSプラットフォームの提供」ではなく「マーケティングチームが希望している
ダッシュボードツールの契約です」。]

[1段落：ステークホルダーが知っておくべきこと。注意点があれば記載。例：
「この契約は毎年自動更新で、解約は2ヶ月前までに通知が必要です。更新台帳に
登録しましたが、ご承知おきください。」または「特に問題のない契約です。
署名に進めます。」]

**ご対応をお願いしたい事項：**
- [ ] [アクション項目。例：「EUにデータが保管される点について、情シス部門に確認」
  または「特になし --- 法務から署名手続きに進めます」]

**承認:** [承認者名]が[タイミング]に承認予定です。
```

### ステップ4: 法務用語の翻訳

| レビューの指摘事項 | ビジネスへの翻訳 |
|---|---|
| 「責任制限が12ヶ月分の委託料に上限設定」 | 「相手方に問題があった場合、回収できるのは最大1年分の利用料までです。」 |
| 「解約権なし（任意解除権の排除）」 | 「署名したら契約期間満了まで解約できません。途中でやめることはできません。」 |
| 「自動更新条項（60日前通知）」 | 「毎年自動で更新されます。解約するには更新日の2ヶ月前までに通知が必要です。」 |
| 「知的財産権の全面譲渡」 | 「成果物の権利がすべて相手方のものになります。自社で再利用できなくなります。」 |
| 「サブプロセッサーリスト非開示」 | 「当社のデータにアクセスできる外部業者が誰なのか、事前に知ることができません。」 |
| 「契約不適合責任の免除」 | 「納品物に問題があっても、修正や返金を求める権利が制限されています。」 |
| 「反社排除条項なし」 | 「反社会的勢力との関係がないことの確認条項が入っていません。追加を要求しています。」 |

### 含めないもの

- 条番号（「第8条第2項」ではなく内容で説明する）
- 法律用語の定義（「債務不履行」ではなく「約束を守らなかった場合」）
- リスクマトリクス（ステークホルダーが事前に希望した場合を除く）
- 「法的助言ではありません」の注記（ステークホルダーは誰が送ったか知っている）

## レビューで問題が見つかった場合

🔴 または 🟠 の指摘事項がある場合でも、サマリーは2段落に収める。2段落目を「修正要求中の事項」に変更する。

```markdown
[秘密保持マーキング]

**[相手方名] [契約類型]** --- 修正必要

[この契約が何をするか、1段落。]

[N]件の修正を相手方に要求しています。主な点は[重要な問題を平易な日本語で ---
「相手方が当社のデータを自社製品の改善に使用できる条項があり、これは競合他社にも
利益が流れることを意味します」]。この条項の削除を求めています。[現実的な見通し：
「おそらく応じてもらえると思います」/「交渉が難航する可能性があります --- 進捗を
お知らせします。」]

**ご対応をお願いしたい事項：**
- [ ] 現時点では特にありません --- 相手方の回答待ちです。
  または
- [ ] [事業判断が必要な場合：「相手方が[X]について譲らない場合、[Y]で妥協してよいか、
  契約見送りとするか、ご判断をお願いします。」]
```

## 配信形式

`~/.claude/plugins/config/claude-for-legal/commercial-legal-jp/CLAUDE.md` の設定に応じて：

**Slack/Teams/Chatwork向け:** 150文字以内。
```
[相手方名] [契約類型] --- 修正必要。1🔴（責任制限条項）、2🟠。フルレビュー: [リンク]。[法務部長]承認必要。
```

**メール向け:** 上記フォーマットをそのまま使用。

## トーンについて

ステークホルダーが法務について覚えている2つのこと：ブロックされたかどうか、わかりやすかったかどうか。このスキルは「わかりやすかった」を実現する手段。スマートな同僚にコーヒーを飲みながら説明するように書く。

正直なサマリーが「問題ありません、署名してください」であれば、そう書く。問題のないレビューを3段落に水増ししない。

## 免責事項

本スキルの出力は法的助言に代わるものではありません。最終的な判断は必ず弁護士にご確認ください。

## このスキルが行わないこと

- 契約書の再レビューは行わない。レビュー結果を読んで圧縮する。
- 法務判断は行わない。レビュー結果をビジネスの言葉に翻訳する。
- 秘密保持マーキングを勝手に外さない。外部転送時にはユーザーが判断して外す。
