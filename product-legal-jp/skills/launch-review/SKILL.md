# /launch-review

## 前提条件

1. `~/.claude/plugins/config/claude-for-legal/product-legal-jp/CLAUDE.md` を読み込み。`[PLACEHOLDER]` が残っている場合は停止し `/product-legal-jp:cold-start-interview` を案内。
2. `~/.claude/plugins/config/claude-for-legal/company-profile.md` を読み込み。

## 入力

- PRDリンク（Drive / Confluence）、チケット番号（Jira / Linear）、またはテキスト貼り付け
- 入力がない場合、ローンチトラッカーから直近のチケットを表示して選択を求める

## AIコンポーネント検出

フレームワークウォーク開始前に、ローンチにAIコンポーネントが含まれるか確認。含まれる場合、カテゴリ8（AIガバナンス）を有効化し、AI事業者ガイドラインに基づく追加チェックを実施。

## 8カテゴリフレームワーク（日本法版）

各カテゴリについて、該当する日本法の観点からレビュー:

### 1. 契約適合性
- 既存の利用規約・SLAとの整合性
- 第三者ライセンス・OSSライセンスの条件充足
- 下請法該当性（資本金要件 + 取引類型）

### 2. 個人情報保護
- 個人情報保護法（APPI）の利用目的との整合性
- 要配慮個人情報の取得有無
- 第三者提供・越境移転の有無
- 外部送信規律（電気通信事業法2023年改正）該当性
- → 詳細が必要な場合は `/privacy-legal-jp:appi-compliance-check` にハンドオフ

### 3. セキュリティ
- データの保管・処理場所
- 暗号化・アクセス制御
- ベンダーセキュリティ評価

### 4. 知的財産
- 商標クリアランス（JPO検索）
- 特許リスク
- 著作権（UGC、コンテンツ利用）
- → 詳細が必要な場合は `/ip-legal-jp` にハンドオフ

### 5. 第三者取引
- ベンダー契約のレビュー状況
- API利用規約の遵守
- データ処理委託契約（APPI第25条）

### 6. 業規制
- セクター固有の規制チェック

セクターオーバーレイ（該当する場合に追加チェック）:

| セクター | 主な規制 | チェック項目 |
|---|---|---|
| 金融 | 金融商品取引法、資金決済法、貸金業法 | 金融商品販売の勧誘方針、暗号資産規制、前払式支払手段 |
| 医療・ヘルスケア | 医療法、医師法、薬機法 | 医療広告ガイドライン、オンライン診療指針 |
| 食品 | 食品表示法、健康増進法、JAS法 | 栄養成分表示、機能性表示食品届出 |
| 化粧品 | 薬機法 | 効能効果の範囲、化粧品の効能効果の範囲に関する通達 |
| 教育 | 学校教育法、私塾関連条例 | 特定継続的役務提供（特商法） |
| 不動産 | 宅建業法 | 不動産の表示に関する公正競争規約 |
| 通信・IT | 電気通信事業法 | 外部送信規律、通信の秘密 |
| ゲーム・エンタメ | 風営法、各種自主規制 | ガチャ（懸賞景品該当性）、年齢制限 |

### 7. 表示・広告
- 景品表示法第5条（優良誤認・有利誤認）
- 不実証広告規制（第7条第2項）
- ステルスマーケティング規制（2023年消費者庁指定告示）
- 比較広告ガイドライン
- 打消し表示に関する実態調査報告書
- 薬機法（健康食品・化粧品の場合）
- → 詳細が必要な場合は `/product-legal-jp:marketing-claims-review` または `/product-legal-jp:keihin-hyouji-check` にハンドオフ

### 8. AIガバナンス（AI コンポーネント検出時のみ）
- AI事業者ガイドライン（経済産業省・総務省）
- 透明性・説明責任
- バイアス・公平性
- → 詳細が必要な場合は `/ai-governance-legal-jp` にハンドオフ

## キャリブレーション

各発見事項をリスクキャリブレーションテーブルに照合:

| 重要度 | 意味 | アクション |
|---|---|---|
| 🔴 ブロッキング | 措置命令・課徴金リスク、重大な法令違反 | リリース前に解決必須 |
| 🟠 高 | 行政指導リスク、規制違反の可能性 | 対応計画が必要 |
| 🟡 中 | 軽微な不備、ベストプラクティスからの逸脱 | 推奨事項として対応 |
| 🟢 低 | FYI、参考情報 | 記録のみ |

## 出力

### 1. レビューメモ（特権付き）

ワークプロダクトヘッダー付き。各カテゴリの発見事項を重要度順に記載。

構成:
1. **エグゼクティブサマリー** — 2-3文。ローンチ可否の結論（条件付き含む）
2. **発見事項テーブル** — カテゴリ・発見事項・重要度・推奨アクション
3. **各発見事項の詳細** — 根拠法令、リスクシナリオ、推奨対応
4. **チェックリストに含まれない観察** — フレームワーク外だが注意すべき点
5. **次のステップ・デシジョンツリー**

### 2. チケットコメント（非特権・トラッカー掲載用）

特権情報を除いた要約。トラッカー（Jira/Linear）に掲載可能な形式:
- ブロッカーの有無
- 必要なアクション項目
- 期限の提案

## ソース帰属

- `[確定 — 最終確認 YYYY-MM-DD]` — 安定した法令で確認日が判明している場合
- `[モデル知識 — 要確認]` — デフォルト
- `[ウェブ検索 — 要確認]` — ウェブ検索で取得した場合
- `[ユーザー提供]` — ユーザーが提供した情報

## 非弁護士ゲート

利用者が弁護士でない場合、「リリース可」の判断を出す前に:

> ⚖️ **弁護士確認ゲート:** 「リリース可」の最終判断には弁護士の確認が必要です。この分析は法的助言ではありません。

⚖️ **弁護士確認ゲート:** この分析は弁護士による確認が必要です。弁護士法第72条により、弁護士でない者が法律事務を取り扱うことは禁止されています。最終的な法的判断は必ず弁護士に確認してください。

📋 **免責事項:** この出力はAIによる分析であり、法的助言を構成するものではありません。景品表示法・特商法・薬機法等の解釈・適用については、必ず弁護士にご確認ください。法令・ガイドラインは頻繁に改正されるため、最新の条文・通達・ガイドラインを確認してください。
