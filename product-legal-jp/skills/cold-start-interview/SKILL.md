# /cold-start-interview

1. `~/.claude/plugins/config/claude-for-legal/product-legal-jp/CLAUDE.md` の状態を確認。
2. 以下のコールドスタートインタビューを実行。
3. シードドキュメント: 過去のローンチレビュードキュメント10件（トラッカーまたはDriveから）。すべて読み込み。
4. 実際にブロックしたもの vs. リリースしたものからリスクキャリブレーションテーブルを構築。
5. マイグレーション: 設定済みの CLAUDE.md（`[PLACEHOLDER]` マーカーなし）が `~/.claude/plugins/cache/claude-for-legal/product-legal-jp/*/CLAUDE.md` に存在するが設定パスにない場合、設定パスにコピーし、マイグレーション内容をユーザーに表示。
6. `~/.claude/plugins/config/claude-for-legal/product-legal-jp/CLAUDE.md` を書き込み（必要に応じて親ディレクトリを作成）。キャリブレーションテーブルを確認のため表示。

## `--check-integrations`

インテグレーション可用性チェック（ローンチトラッカー、ドキュメントストレージ、Slack）のみ再実行し、`~/.claude/plugins/config/claude-for-legal/product-legal-jp/CLAUDE.md` の `## 利用可能なインテグレーション` を更新。再インタビューは行いません。MCPの接続・切断時にフルセットアップなしでプラグインに通知するために使用。

プローブ時: MCPツールコールが実際に成功した場合のみ ✓ を報告。設定済みだがテスト未実施のコネクタは ⚪ とし、確認方法を1行記載。`.mcp.json` の宣言だけで ✓ を報告しないでください。

## クイックスタート vs. フルセットアップ

冒頭で提示:
- **クイックスタート（2分）:** Part 0 + Part 1 の必須項目のみ。日本法の基本設定で開始し、後で `/product-legal-jp:customize` で調整可能。
- **フルセットアップ（15分）:** 全パートを実行。シードドキュメントからキャリブレーションテーブルを構築。

## インストールスコープチェック

冒頭で `claude plugin list` を実行。このプラグインがプロジェクトスコープでインストールされている場合、ユーザーに通知: 「このプラグインはプロジェクトスコープ（[project dir] のみ）でインストールされています。すべてのプロジェクトで使用する場合は `claude plugin install --scope user product-legal-jp` でユーザースコープに変更してください。」

## 共有会社プロファイルチェック

`~/.claude/plugins/config/claude-for-legal/company-profile.md` を読み込み。存在しない場合、Part 1 で作成。存在する場合、その値を Part 1 で表示し、更新が必要か確認。

## Part 0: 利用者分類・インテグレーション

### 利用者分類

「あなたの役割を教えてください:」

1. **弁護士** — 日本の弁護士資格を保有
2. **弁護士アクセスのある法務担当者** — 社内または外部に確認可能な弁護士がいる
3. **弁護士アクセスのない非法律職** — PM・マーケター等で弁護士への直接アクセスなし

選択肢2または3の場合:

> ⚖️ **弁護士法第72条に関する重要な注意:** このプラグインは法的分析・リスク評価を提供しますが、法的助言ではありません。弁護士法第72条により、弁護士でない者が法律事務を取り扱うことは禁止されています。最終的な法的判断は必ず弁護士に確認してください。すべての出力に弁護士確認ゲートを付記します。

### インテグレーション確認

以下を順番にプローブ — 各ツールに対して実際のAPI呼び出しを試行:

1. **ローンチトラッカー** — Linear、Jira、Asanaの順にプロジェクト一覧を試行
2. **ドキュメントストレージ** — Google Drive でファイル一覧を試行
3. **コミュニケーション** — Slack でチャンネル一覧を試行

結果を表で表示:

|---|---|---|
| [名前] | ✓ 接続済 / ✗ 未接続 / ⚪ 設定済・未テスト | [詳細] |

## Part 1: 会社情報（company-profile.md を読み込み済みの場合は確認のみ）

以下を質問:

1. **会社名・製品名:** 何を作っていますか？
2. **BtoC / BtoB / 両方:** エンドユーザーは誰ですか？
3. **規制業種:** 特定の業規制がありますか？（金融、医療、食品、化粧品、健康食品、通信、教育等）
4. **会社ステージ:** シード / シリーズA-D / プレIPO / 上場 / PE傘下
5. **リスク許容度:** 保守的 / 中間 / 積極的
6. **法務チーム構成:** 法務部門の規模、プロダクト法務専任の有無
7. **過去の行政処分・措置命令:** 消費者庁や公正取引委員会から措置命令・行政指導を受けた経験があるか
8. **稟議制度:** 法務レビューの承認フロー（稟議が必要な場合、承認者・金額閾値）
9. **海外展開:** 越境EC、海外向けマーケティングの有無

---

## Part 2: レビュープロセス・フレームワーク

1. **ローンチが法務にどう届くか:** Slack / チケット / 定例会議 / アドホック
2. **リードタイム:** ローンチ前何日で法務に来るか
3. **レビューフレームワーク:** 現在の8カテゴリ（契約適合性、個人情報保護、セキュリティ、知的財産、第三者取引、業規制、表示・広告、AIガバナンス）について、各カテゴリの重要度・カスタマイズ
4. **P0 vs. FYI:** 何がブロッカーで何がFYIか — 具体例を聞く

---

## Part 3: 広告表示・マーケティング

1. **広告審査体制:** 社内で広告表示の事前審査があるか、誰が担当か
2. **過去の問題事例:** 景品表示法・薬機法・特商法に関連する問題が過去にあったか
3. **比較広告の方針:** 比較広告を使うか、公正取引委員会の比較広告ガイドラインに沿った運用か
4. **不実証広告規制への対応方針:** エビデンスの管理体制、15日以内の立証資料準備能力
5. **インフルエンサーマーケティング:** ステルスマーケティング（2023年消費者庁指定告示）への対応方針
6. **景品キャンペーン:** キャンペーン・プロモーション実施の頻度と種類（懸賞/総付景品）
7. **薬機法関連:** 健康食品・化粧品・サプリメント等の広告を行うか

---

## Part 4: シードドキュメント

「過去のローンチレビュードキュメントを5-10件共有してください — Drive上のフォルダ、ドキュメントリンク、またはテキスト貼り付けで。」

シードドキュメントから抽出:

1. **実際にブロックしたもの** — 措置命令リスク、薬機法違反リスク、特商法表示不備等
2. **対応が必要だったがリリースしたもの** — 打消し表示追加、比較広告修正、景品上限調整等
3. **FYIだったもの** — 軽微な表現修正、参考情報の共有等

これらからリスクキャリブレーションテーブルを構築。

## 書き込み

すべてのインタビュー結果を `~/.claude/plugins/config/claude-for-legal/product-legal-jp/CLAUDE.md` に書き込み:
- `[PLACEHOLDER]` を実際の値に置換
- リスクキャリブレーションテーブルを完成
- company-profile.md がない場合は作成
- 設定パスの親ディレクトリを必要に応じて作成

書き込み後:
1. キャリブレーションテーブルを表示して確認を求める
2. プラグインの機能一覧を表示（利用可能なスキルと主な用途）
3. 最初のタスクを提案（例: 「直近のローンチで `/product-legal-jp:launch-review` を試してみませんか？」）
4. `/product-legal-jp:launch-review` のローンチ監視エージェントを提案
