

# claude-for-legal 日本法適応プロジェクト 計画書

## 1. エグゼクティブサマリー

### 1.1 プロジェクトの目的

本プロジェクトは、Anthropic社のClaude Code向け法務プラグインマーケットプレイス「claude-for-legal」（12の第一者プラグイン、1つのベンダープラグイン、5つの管理エージェントクックブックで構成）を、日本の法律実務に適応させるリバースエンジニアリングおよびローカライズプロジェクトである。

現行プラグイン群は米国のコモンロー体系、連邦・州法の二層構造、FRCP（連邦民事訴訟規則）に基づくディスカバリー制度、attorney-client privilege（弁護士依頼者間秘匿特権）およびwork-product doctrine（弁護士成果物保護法理）を前提に構築されている。日本は大陸法（シビルロー）体系であり、制定法（六法＋特別法）を第一次法源とし、判例は法的拘束力（stare decisis）を持たないが、事実上の拘束力（de facto binding effect）を有し、判例変更には最高裁大法廷での審理が必要である（裁判所法第10条第3号）。この根本的差異により、単なる翻訳ではなく、法的実体の再構築が必要となる。

### 1.2 適応方針の概要

全12プラグインの分析結果に基づき、適応方針を以下の4段階に分類した。

| 適応レベル | 対象プラグイン | 概要 |
|---|---|---|
| 全面書換え | privacy-legal, litigation-legal, employment-legal | 法制度の根本的差異により、スキルの大半を一から再構築する必要がある |
| 大幅改修 | commercial-legal, corporate-legal, regulatory-legal, ai-governance-legal, ip-legal | 構造は活用可能だが、法的実体の大部分を日本法に置換する必要がある |
| 部分改修 | product-legal, legal-clinic, law-student | 一部構造を維持しつつ、法的参照先・用語・手続を日本法に変更する |
| 基盤改修 | legal-builder-hub | メタプラグインとして、日本法対応の基盤フレームワークを整備する |

### 1.3 推定工数と優先順位

| フェーズ | 対象 | 推定期間 | 推定工数（人月） |
|---|---|---|---|
| Phase 1（MVP） | commercial-legal, employment-legal, corporate-legal, 共通基盤 | 4-6ヶ月 | 24-36人月 |
| Phase 2（拡張） | privacy-legal, litigation-legal, product-legal, regulatory-legal | 4-6ヶ月 | 28-40人月 |
| Phase 3（完成） | ai-governance-legal, ip-legal, law-student, legal-clinic, legal-builder-hub, 新規プラグイン | 4-6ヶ月 | 20-30人月 |
| 合計 | 全12プラグイン＋新規 | 12-18ヶ月 | 72-106人月 |

上記工数には、弁護士によるレビュー、テスト、フィードバック反映を含む。日本法の正確性担保のため、各フェーズにおいて少なくとも2名の日本法弁護士（うち1名は当該分野の専門家）によるレビューを必須とする。

## 2. 基本設計方針

### 2.1 アーキテクチャ方針

既存のプラグイン構造（`.claude-plugin/plugin.json`、`.mcp.json`、`CLAUDE.md`、`skills/`、`agents/`、`hooks/`）をそのまま踏襲する。これにより、claude-plugins-officialのCI検証（I1-I11のマーケットプレイス不変条件）との互換性を維持する。

日本法版プラグインは、以下の命名規則に従い、原則として既存プラグインとは別のディレクトリに配置する。

```
commercial-legal-jp/
  .claude-plugin/plugin.json    # name: "commercial-legal-jp"
  .mcp.json                     # 日本のリーガルテック連携
  CLAUDE.md                     # 日本法プラクティスプロファイルテンプレート
  skills/
    review/SKILL.md             # 日本法の契約レビュー
    vendor-agreement-review/SKILL.md
    shitauke-ho-check/SKILL.md  # 新規：下請法チェック
    ...
```

marketplace.jsonには日本法版プラグインを追加エントリとして登録する。既存の英語版プラグインは維持し、ユーザーが言語・法域に応じて選択できるようにする。

### 2.2 共通ガードレールの日本法対応

全プラグインに共通するガードレール体系を、以下のとおり日本法に適応させる。

#### 2.2.1 秘匿特権ヘッダーの廃止と秘密保持マーキングの導入

**現行（米国版）：**
```
PRIVILEGED & CONFIDENTIAL — ATTORNEY WORK PRODUCT —
PREPARED AT THE DIRECTION OF COUNSEL
```

**日本版（弁護士ユーザー）：**
```
秘密 — 弁護士業務上の秘密（弁護士職務基本規程第23条（秘密の保持）、刑法第134条第1項（秘密漏示罪））— 社外秘
```

**日本版（非弁護士・法務部員）：**
```
社外秘 — 法的助言に代わるものではありません — 弁護士にご確認ください
```

理由：日本にはFRCP 26(b)(3)に基づくwork-product doctrineに相当する制度が存在しない。弁護士職務基本規程第23条（秘密の保持）及び刑法第134条第1項（秘密漏示罪）は秘密保持義務を定めるが、これは弁護士個人の職業上の義務であり、文書そのものに証拠法上の保護を与える米国の特権（privilege）とは本質的に異なる。日本の民事訴訟において、文書提出命令（民事訴訟法第220条）に対し「attorney work product」であることを理由に提出を拒むことはできない。したがって、米国式の特権ヘッダーは日本では法的効力を持たず、虚偽の保護を主張することになるため、秘密管理区分に基づくマーキングに置き換える。

#### 2.2.2 弁護士法第72条ゲートの強化

弁護士法第72条（非弁行為の禁止）は、弁護士でない者が報酬を得る目的で法律事務を取り扱うことを禁止しており、違反には刑事罰（2年以下の懲役又は300万円以下の罰金）が科される。米国のUPL（unauthorized practice of law）規制が州ごとに異なり民事制裁にとどまることが多いのに対し、日本の規制はより厳格である。

全プラグインにおいて、以下の三段階のユーザー分類を採用する。

| 分類 | 定義 | ゲート制御 |
|---|---|---|
| 弁護士（企業内弁護士を含む） | 日本弁護士連合会に登録された弁護士 | 全機能利用可能。秘密保持義務の遵守を前提 |
| 法務部員等（弁護士資格なし、顧問弁護士あり） | 弁護士資格を持たないが、顧問弁護士への相談アクセスを有する | 分析・調査機能は利用可能。法的助言に該当する出力（契約書の最終判断、訴訟方針の決定等）には弁護士確認ゲートを設置 |
| その他（弁護士資格なし、顧問弁護士なし） | 弁護士へのアクセスがない | 分析・調査機能のみ利用可能。法的助言に該当する出力は一切生成せず、弁護士紹介（日弁連・各地弁護士会・法テラス）を案内 |

弁護士紹介先の標準テンプレート：
```
弁護士への相談をお勧めします。以下の機関で弁護士の紹介を受けることができます。
- 日本弁護士連合会（日弁連）弁護士紹介制度
- お住まいの地域の弁護士会（例：東京弁護士会、第一東京弁護士会、第二東京弁護士会）
- 法テラス（日本司法支援センター）：0570-078374
```

#### 2.2.3 ソース帰属（Source Attribution）の日本法対応

三段階の検証システム（[確定]／[要確認]／[要精密確認]）は法域横断的に有効であるため維持する。ソースタグの語彙を以下のとおり置換する。

| 現行タグ（米国版） | 日本版タグ |
|---|---|
| [Westlaw] | [Westlaw Japan] |
| [CourtListener] | [裁判所ウェブサイト] |
| [Trellis] | [LEX/DB] |
| [Descrybe] | [D1-Law] |
| [Federal Register] | [e-Gov法令検索] |
| [model knowledge — verify] | [モデル知識 — 要確認] |
| [settled — last confirmed YYYY-MM-DD] | [確定 — 最終確認日 YYYY-MM-DD] |

判例引用形式は日本の慣行に従う：
```
最判平成10年2月24日民集52巻1号113頁（ボールスプライン事件）
東京地判令和5年3月15日判時2550号10頁
個人情報保護法第28条第1項
```

#### 2.2.4 法令更新トリガー（Currency Watch）の日本法対応

日本法の改正サイクルに基づき、以下を監視対象とする。

- 民法・商法・会社法の改正（例：2020年民法改正による瑕疵担保責任から契約不適合責任への変更）
- 個人情報保護法の3年ごとの見直し（次回見直し時期の追跡）
- 公正取引委員会のガイドライン更新（下請法運用基準、優越的地位の濫用ガイドライン等）
- 各省庁の審議会報告書・中間とりまとめ（法改正の上流シグナル）
- 最高裁判所の重要判例（判例変更を含む）

#### 2.2.5 重大度分類（Severity Scale）の日本語化

| スケール | 日本語ラベル | 説明 |
|---|---|---|
| 🔴 | 対応必須 | 法的義務違反のリスク、行政処分・課徴金の可能性 |
| 🟠 | 重要 | 重大なリーガルリスク、顧問弁護士への相談推奨 |
| 🟡 | 要確認 | リスクはあるが許容範囲内の可能性、追加調査推奨 |
| 🟢 | 低リスク | 現時点で重大なリスクなし、経過観察 |

### 2.3 言語対応方針

全出力テンプレート、ガードレール警告、意思決定ツリー、インタビュー質問を日本語で提供する。法律用語は正確な日本語法令用語を使用し、以下のルールを適用する。

- 法令用語は法令に定められた表記を使用する（例：「善管注意義務」ではなく「善良な管理者の注意義務」が正式だが、実務では前者が通用しているため前者を使用し、初出時に正式名称を注記する）
- 2020年民法改正後の用語を使用する（「瑕疵担保責任」→「契約不適合責任」。ただし改正前の法律を議論する場合は旧用語を使用し注記する）
- クロスボーダー取引では、契約書が英語の場合は英語の契約条項をそのまま引用し、分析は日本語で行う
- 敬語レベルは文書の性質に応じて使い分ける：対外文書は「ですます調」、内部分析メモは「である調」

## 3. プラグイン別適応計画

### 3.1 commercial-legal（商事法務プラグイン）

**適応方針：大幅改修**

日本の企業間取引契約実務に対応するため、法的実体の大部分を日本法に置換する。契約レビューの構造（段階的レビュー、エスカレーション、ステークホルダーサマリー）は活用可能。

#### 3.1.1 根本的差異への対応

**(a) コモンロー→シビルローの転換**

米国版の判例法ベースのプレイブック・ポジション（Hadley v. Baxendale型の予見可能性テスト等）を、日本の制定法に基づくフレームワークに置換する。

| 米国の概念 | 日本法の対応 | 根拠法令 |
|---|---|---|
| Consequential damages / Direct damages | 通常損害 / 特別損害 | 民法第416条 |
| Breach of contract | 債務不履行 | 民法第415条 |
| Tort liability | 不法行為 | 民法第709条 |
| Warranty of fitness | 契約不適合責任 | 民法第562条-第564条 |
| Indemnification / Hold harmless | 損害賠償条項 | 民法上の概念として再構成 |
| Termination for convenience | 解除 | 民法第540条-第548条 |
| Limitation of liability | 責任制限条項 | 合意に基づくが、故意・重過失の免責は公序良俗（民法第90条）により無効となりうる |
| Governing law (Delaware/NY preference) | 準拠法・管轄 | 日本法＋東京地方裁判所/大阪地方裁判所 |

**(b) 下請法コンプライアンスの追加（新規要素）**

下請法（下請代金支払遅延等防止法）は米国法に同等の規制がなく、日本の商事契約レビューにおいて不可欠な要素である。親事業者と下請事業者の関係において、資本金区分と取引類型（製造委託、修理委託、情報成果物作成委託、役務提供委託）に基づき適用が判断される。

資本金区分による適用基準は以下のとおり：
- 製造委託・修理委託：親事業者の資本金3億円超→下請事業者の資本金3億円以下、又は親事業者の資本金1千万円超3億円以下→下請事業者の資本金1千万円以下
- 情報成果物作成委託・役務提供委託：親事業者の資本金5千万円超→下請事業者の資本金5千万円以下、又は親事業者の資本金1千万円超5千万円以下→下請事業者の資本金1千万円以下

違反行為の類型：受領拒否、下請代金の減額、返品、買いたたき、不当な給付内容の変更、報復措置等。3条書面（発注書面）の交付義務、60日以内の代金支払義務が課される。

**(c) 反社会的勢力排除条項の必須チェック（新規要素）**

日本の契約実務では、反社会的勢力排除条項（暴力団排除条項）が事実上の必須条項である。全47都道府県の暴力団排除条例、全国銀行協会・経団連等の業界ガイドラインがこれを要求している。

### 3.2 privacy-legal（個人情報保護プラグイン）

**適応方針：全面書換え**

EU GDPR・米国連邦セクター法（HIPAA、FERPA、COPPA、GLBA）を前提とした規制フレームワークを、個人情報保護法（APPI）を中心とする日本の個人情報保護法制に全面的に置換する必要がある。

#### 3.2.1 根本的差異への対応

**(a) 規制フレームワークの全面置換**

| 米国/EU概念 | 日本法の対応 | 根拠法令 |
|---|---|---|
| GDPR controller/processor | 委託者/受託者 | APPI第25条 |
| GDPR DPA (Data Processing Agreement) | 委託契約（個人データ取扱いに関する覚書） | APPI第25条（委託先の監督） |
| GDPR Art. 35 DPIA | 特定個人情報保護評価（マイナンバー法）/ PPC推奨のPIA | マイナンバー法、PPC告示 |

### 3.4 corporate-legal（会社法務プラグイン）

**適応方針：大幅改修**

Delaware会社法を前提としたガバナンス構造を、日本の会社法に基づく三種のガバナンスモデルに対応させる。

### 3.5 employment-legal（労働法務プラグイン）

**適応方針：全面書換え**

米国のat-will employment（随意雇用）を前提とした全フレームワークを、日本の解雇権濫用法理を中心とする厳格な雇用保護法制に全面的に再構築する。これは全12プラグイン中、最も根本的な転換を要する。

#### 3.5.1 根本的差異への対応

**(a) 解雇法制の根本的転換**

| 米国概念 | 日本法の対応 | 根拠法令 |
|---|---|---|
| At-will employment (default) | 解雇権濫用法理（解雇は「客観的に合理的な理由」＋「社会通念上の相当性」が必要） | 労働契約法第16条 |
| WARN Act (mass layoff) | 整理解雇4要件（人員削減の必要性、解雇回避努力義務、人選の合理性、手続の妥当性） | 判例法理 |
| OWBPA (older workers) | 高年齢者雇用安定法（65歳までの雇用確保義務、70歳までの就業確保措置） | 高年齢者雇用安定法 |
| Severance agreement | 退職合意書＋退職勧奨（退職強要にならない範囲で） | — |
| Final pay timing (state-specific) | 退職時7日以内（請求があった場合） | 労働基準法第23条 |
| FMLA (12 weeks) | 育児休業（子が1歳まで、延長で2歳まで）＋介護休業（93日）等 | 育児介護休業法 |
| Exempt/Non-exempt (FLSA) | 管理監督者（労基法第41条）— 極めて狭い解釈（名ばかり管理職判例） | 労働基準法第41条 |
| ABC test / IC classification | 労働者性判断基準（指揮監督下の労働＋報酬の労務対償性） | 厚労省ガイドライン＋判例 |
| EEOC / Title VII | 男女雇用機会均等法＋パワハラ防止法 | 均等法、労働施策総合推進法 |

**(b) 就業規則の法的拘束力**

米国のemployee handbookが原則として使用者の政策文書にすぎないのに対し、日本の就業規則（常時10人以上の労働者を使用する事業場で作成義務）は法的拘束力を有し、労働基準監督署への届出が義務付けられている。不利益変更には労働契約法第9条-第10条の合理性テストが適用される。

### 3.8 litigation-legal（訴訟法務プラグイン）

**適応方針：全面書換え**

米国の当事者主義的訴訟制度（広範なディスカバリー、陪審裁判、デポジション）を前提とした全フレームワークを、日本の職権主義的要素を含む民事訴訟制度に全面的に再構築する。

#### 3.8.1 根本的差異への対応

| 米国概念 | 日本法の対応 | 差異の本質 |
|---|---|---|
| Discovery (FRCP 26-37) | 日本には米国式の広範なディスカバリー制度は存在しないが、文書提出命令（民訴法第220条-第231条）、証拠保全（民訴法第234条-第242条）、当事者照会（第163条）、弁護士会照会（弁護士法第23条の2）、調査嘱託（第186条）、文書送付嘱託（第226条）が証拠収集手段として利用可能 | 各手段とも裁判所の関与が必要であり、米国のような当事者主導の広範な開示制度はない |

| Privilege log (FRCP 26(b)(5)(A)) | **存在しない** — 秘密文書の保護は文書提出命令への異議（民訴法第220条第4号）で行う | 特権ログという制度がない |
| Jury trial | **民事では存在しない**（裁判員制度は重大刑事事件のみ） | 裁判官が事実認定と法律判断の両方を行う |
| Class action | **米国式は存在しない** — 消費者裁判手続特例法による限定的集団訴訟 | 集団訴訟のリスクが根本的に異なる |
| Subpoena (FRCP 45) | 当事者の申立てに基づき裁判所が発する文書提出命令（民訴法第221条）。文書送付嘱託（第226条）・調査嘱託（第186条）・当事者照会（第163条）・弁護士会照会（弁護士法第23条の2）も利用可能 | 米国のsubpoenaと異なり、当事者が直接相手方に強制力を行使する制度ではない |

### 5.3 ガードレール体系の日本法対応（まとめ）

第2.2節で詳述した共通ガードレールに加え、以下の横断的ガードレールを設ける。

#### 5.3.1 法域認識ガードレール（Jurisdiction Recognition）

**米国版（デフォルト＝米国）：** 非米国法域の事実を検出したら警告

**日本版（デフォルト＝日本）：** 日本法をデフォルトとし、米国法・EU法・その他外国法の適用可能性がある場合に警告。例：
- データ主体がEU域内にいる場合 → GDPR適用の可能性を警告
- 契約相手方が米国法人の場合 → 米国法の適用可能性を警告
- クロスボーダーM&A → 複数法域の規制を警告

#### 5.3.2 決定態度ガードレール（Decision Posture）

「回復可能なエラーを好む」原則と[要検討]フラグシステムは法域横断的に有効であるため維持する。ただし、主観的法的判断の例示を日本法に変更する。

例：
- 「この条項が優良誤認に該当するか否かは、消費者庁の過去の措置命令事例と比較して判断する必要があります。[要弁護士判断]」
- 「契約不適合責任の期間制限が著しく短い場合、消費者契約法に基づき無効となる可能性があります。[要確認]」

## 7. リスクと課題

### 7.1 法的正確性の担保

**リスク：** AIが生成する法的分析の正確性は、プロンプト（SKILL.md、CLAUDE.md）に記載される法的ルールの正確性に依存する。日本法の誤った記述は、ユーザーに誤った法的判断を誘導する可能性がある。

**対策：**
- 各プラグインにつき、当該分野の専門弁護士（実務経験5年以上）によるレビューを必須とする
- 法令引用は全てe-Gov法令検索で最新条文を確認する
- 判例引用は裁判所ウェブサイトまたは判例データベースで原文を確認する
- 法改正時の更新手順をドキュメント化する（Currency Watchガードレールと連動）
- 全出力に「法的助言に代わるものではありません — 弁護士にご確認ください」の注記を含める

### 7.2 弁護士法第72条との整合性

**リスク：** プラグインの出力が「法律事務」に該当する場合、非弁護士ユーザーによる利用が弁護士法第72条に抵触する可能性がある。

**対策：**
- 三段階ユーザー分類（弁護士/顧問弁護士あり法務部員/その他）の厳格な実装
- 非弁護士ユーザーに対しては、「法律事務」に該当しうる出力（法的助言、契約書の最終判断、訴訟方針の決定等）を生成しない
- 「分析・調査の補助ツール」としてのポジショニングを明確化する
- 日弁連の見解・ガイダンスが発表された場合は速やかに反映する

### 7.3 日本のリーガルテックエコシステムとの連携

**リスク：** 日本のリーガルテック製品（クラウドサイン、LegalForce、MNTSQ等）のMCPコネクターが存在しない、または利用制限がある可能性がある。

**対策：**
- MCP連携は`recommendedCategories`として推奨にとどめ、連携がなくてもプラグインが動作するよう設計する
- 主要リーガルテック企業との事前協議（MCP対応の意向確認）
- 段階的にMCP連携を拡充するロードマップを策定する

### 7.4 法改正への追従

**リスク：** 日本法は頻繁に改正される（例：民法改正、個人情報保護法の3年ごとの見直し、毎年の税制改正等）。プラグインのプロンプト内容が陳腐化する可能性がある。

**対策：**
- Currency Watchガードレールに基づく定期的な法令確認（最低四半期ごと）
- 主要法改正の施行日カレンダーの管理
- 審議会・中間とりまとめの段階から改正動向を把握し、施行前に対応準備を行う
- 法改正情報の更新を担当する専任チームまたは外部弁護士との継続的契約

### 7.5 言語品質の確保

**リスク：** 法律用語の翻訳・使用が不正確な場合、法務専門家からの信頼を損なう。

**対策：**
- 法令用語は法令の原文表記に従う（独自の言い換えを避ける）
- 法律用語の統一辞書（ターミノロジーリスト）を作成し、全プラグインで共有する
- 2020年民法改正後の用語を使用する（瑕疵担保責任 → 契約不適合責任等）
- 日本語ネイティブの法務専門家によるプルーフリーディングを全プラグインに実施する

### 7.6 クロスボーダー案件への対応

**リスク：** 日本企業は国際取引を多く行っており、日本法のみのプラグインでは対応が不十分な場合がある。

**対策：**
- 英語版プラグインを維持し、ユーザーが案件の性質に応じて切り替えられるようにする
- 日本法版プラグインにクロスボーダー認識ガードレールを設け、外国法の適用可能性がある場合に警告する
- 主要なクロスボーダー場面（海外へのデータ移転、外資によるM&A、国際契約の準拠法）については日本法版プラグイン内で基本的なガイダンスを提供する

## 8. 製品戦略

### 8.1 競合分析

日本のリーガルテック市場における主要競合製品との差別化を明確にする。

| 製品 | 主要機能 | claude-for-legal-jpの差別化ポイント |
|---|---|---|
| LegalForce（契約レビューAI） | 契約書レビュー、リスク検出 | LegalForceは契約レビュー特化。claude-for-legal-jpは12の法務分野を横断的にカバーし、プレイブック駆動型で組織固有のポジションに基づく分析を提供 |
| MNTSQ（契約管理） | 契約データベース、期限管理 | MNTSQは契約管理・検索が中心。claude-for-legal-jpはレビュー・分析・起案を含むエンドツーエンドのワークフローを提供 |
| GVA assist（契約レビュー） | 契約書レビュー、条文修正提案 | GVA assistは契約レビュー特化。claude-for-legal-jpはエスカレーション、ステークホルダーサマリー、プレイブック学習ループを含む |
| クラウドサイン | 電子署名・締結 | 競合ではなく補完関係。MCP連携によるシームレスな統合を目指す |

**ターゲットユーザーペルソナ：**
- 一次ターゲット：企業内弁護士（インハウスローヤー）及びClaude Codeを既に利用している法務部門
- 二次ターゲット：中小規模の法律事務所（先進的ITツール導入に積極的な事務所）
- Claude Codeのターミナルベース環境に親和性のあるユーザーを初期ターゲットとし、将来的にIDE拡張やWebアプリでの利用も視野に入れる

### 8.2 セキュリティ・コンプライアンス要件

法務データは機密性が極めて高いため、以下の要件を満たす設計とする。

- **データ送信先・保存先：** Claude APIへの送信データの取り扱いポリシーを明示。Anthropicのデータ保持ポリシー（APIデータは学習に使用されない）を文書化
- **オンプレミス/プライベートクラウド対応：** 大手企業向けにAmazon Bedrock経由でのデプロイオプションを検討
- **認証・認可：** ISO 27001/SOC 2認証の取得計画を策定
- **日本国内リージョン：** AWS東京リージョンでの処理を原則とし、データの海外移転が発生する場合はAPPI第28条に基づく越境移転規制への対応を文書化
- **契約書データの取り扱い：** 入力された契約書データのキャッシュ・保存・削除ポリシーを明確化

### 8.3 弁護士法第72条の規制動向への対応

2026年1月の規制改革推進会議での議論等、弁護士法第72条の解釈・運用の見直し動向を注視し、ゲート設計に柔軟性を持たせる。

- 規制緩和シナリオ：ゲート設定をfeature flagで管理し、規制環境の変化に応じて段階的に緩和可能な設計とする
- 規制強化シナリオ：現行の三段階ゲートをさらに厳格化できるよう、ゲートロジックを設定ファイルで外部化する
- 日弁連の見解・ガイダンスが発表された場合は速やかに反映する体制を構築する
