# 個人関連情報チェック（APPI第31条）

## 案件コンテキスト

**案件コンテキスト。** プラクティスレベルCLAUDE.mdの `## 案件ワークスペース` を確認。`有効` が `✗` の場合スキップ。

---

## 目的

2022年APPI改正で導入された「個人関連情報」の規制（第31条）について、第三者提供のコンプライアンスをチェックする。Cookie、広告ID、閲覧履歴、位置情報等の個人関連情報を第三者に提供し、提供先で個人データとして取得されることが想定される場合の確認義務を評価する。

## 個人関連情報とは

### 定義（APPI第2条第7項）

「個人関連情報」とは、生存する個人に関する情報であって、個人情報、仮名加工情報及び匿名加工情報のいずれにも該当しないものをいう。

### 典型例

| データ種類 | 個人関連情報該当性 | 備考 |
|---|---|---|
| Cookie ID | 該当 | 単体では個人を識別できないが、個人に関する情報 |
| 広告ID（IDFA/GAID） | 該当 | デバイスに紐づく識別子 |
| 閲覧履歴 | 該当 | 個人を特定しない形での閲覧記録 |
| 購買履歴（非特定） | 該当 | 個人を特定しない形での購買記録 |
| 位置情報（非特定） | 該当 | 個人を特定しない形での位置記録 |
| IPアドレス | 該当の可能性 | 状況により個人情報に該当する場合もある |
| ハッシュ化されたメールアドレス | 要判断 | 容易照合性の有無による |

### 三層構造の整理

```
個人情報 ⊃ 個人データ ⊃ 保有個人データ
    ↕（別カテゴリ）
仮名加工情報
匿名加工情報
個人関連情報 ← このスキルの対象
```

## ステップ1: 該当性判定

### 第31条の適用要件

第31条が適用されるには、以下の**すべて**を満たす必要がある：

1. **提供元が個人関連情報を保有している**
2. **第三者に提供する**
3. **提供先において個人データとして取得されることが想定される**

### 「個人データとして取得されることが想定される」の判断

以下のいずれかに該当する場合、「想定される」と判断：

- 提供先が個人関連情報をDMPで突合し、個人情報と紐づけることが想定される
- 提供先が広告配信プラットフォームで個人のプロファイルに統合することが想定される
- 提供先がCRMデータと突合して個人を特定することが想定される
- 提供元が提供先での利用方法を認識しており、個人データ化が合理的に想定できる

### 判定フローチャート

```
個人関連情報を第三者に提供するか？
  ├─ NO → 第31条の適用なし
  └─ YES
      提供先で個人データとして取得されることが想定されるか？
        ├─ NO → 第31条の適用なし（ただし監視を推奨）
        └─ YES
            → 第31条の確認義務が発生
            → ステップ2へ
```

## ステップ2: 確認義務の履行チェック

第31条に基づき、提供元は以下を確認する義務がある：

| # | 確認事項 | 重大度 | 結果 |
|---|---|---|---|
| 2.1 | 提供先が本人の同意を取得していること（または取得することが見込まれること）の確認 | 🔴 | |
| 2.2 | 確認方法が適切か（提供先からの申告、契約条項、同意取得画面の確認等） | 🟠 | |
| 2.3 | 外国にある第三者への提供の場合、第28条の規制も適用されるか | 🔴 | |
| 2.4 | 確認の記録を作成・保存しているか | 🟠 | |

### 提供先の同意取得の確認方法

PPCガイドラインで認められる確認方法：
- 提供先から同意取得済みである旨の申告を受ける
- 提供先の同意取得画面を確認する
- 契約で提供先に同意取得義務を課す

### オプトアウトとの関係

個人関連情報の提供にはオプトアウト方式は認められない。本人同意が必要。

## ステップ3: DMP・広告プラットフォーム連携の評価

特にデジタルマーケティングにおける個人関連情報の利用について：

| 連携パターン | リスク | チェックポイント |
|---|---|---|
| **自社Cookie → DMP** | 🔴 | DMPで他社データと突合される場合、個人データ化が想定される |
| **自社Cookie → 広告プラットフォーム** | 🔴 | リターゲティング広告で個人に到達する場合 |
| **閲覧履歴 → レコメンドエンジン（第三者）** | 🟠 | 提供先での個人データ化の有無を確認 |
| **位置情報 → 分析サービス（第三者）** | 🟠 | 統計化されるか個人レベルで利用されるか |
| **広告ID → アトリビューション計測** | 🟠 | 提供先での利用方法を確認 |

### 電気通信事業法の外部送信規律との交差

外部送信規律（電気通信事業法第27条の12）と個人関連情報規制は重畳適用される場合がある。電気通信事業者に該当する場合は、`/privacy-legal-jp:telecom-external-transmission-check` も実行を推奨。

## ステップ4: 仮名加工情報・匿名加工情報との区分確認

| データの状態 | 分類 | 第三者提供の可否 |
|---|---|---|
| 加工なし（個人を特定可能） | 個人情報/個人データ | 第27条（本人同意等） |
| 仮名加工（復元不可能ではない） | 仮名加工情報 | 原則禁止（第41条第6項） |
| 匿名加工（復元不可能） | 匿名加工情報 | 可能（公表義務あり、第43条） |
| 個人を特定できないが個人に関する | 個人関連情報 | 第31条の確認義務 |

データの加工レベルが不十分で、意図した分類に該当しない場合、規制の適用が変わる。

## 弁護士確認ゲート

利用者が「法務部員等」または「その他」の場合：

> ⚖️ **弁護士確認ゲート:** 個人関連情報の第三者提供に関する確認義務の判断は、データの性質と提供先での利用方法に依存する法的判断です。特にDMP連携や広告プラットフォームとの連携については、弁護士の確認を得てください。

## このスキルが行わないこと

- Cookie同意バナーの技術的実装は行わない — CMP設定はエンジニアリングの役割
- 個人情報と個人関連情報の最終的な分類判断は行わない — 判断材料の提示まで
- GDPR ePrivacy指令に基づくCookie規制は対象外 — `privacy-legal` プラグインを使用
- DMP・広告プラットフォームの技術的な設定変更は行わない
- 個人関連情報の匿名加工処理は行わない

## 免責事項

本チェックはAPPI第31条に基づく個人関連情報の第三者提供規制のコンプライアンス評価支援であり、個人情報保護委員会の公式な判断を代替するものではありません。個人関連情報と個人情報の境界は事案ごとに異なるため、弁護士の確認を得てから対応方針を決定してください。
