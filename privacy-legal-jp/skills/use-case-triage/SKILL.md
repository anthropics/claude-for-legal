# /use-case-triage

1. `~/.claude/plugins/config/claude-for-legal/privacy-legal-jp/CLAUDE.md` を読み込む。PLACEHOLDERの場合は停止してセットアップを案内。
2. 処理活動が不明確な場合は明確化する。
3. ハウストリガーチェック → APPI固有チェック → ポリシー整合性チェック。
4. 出力：分類（進行可 / PIA必要 / 停止） + 理由 + 条件テーブル。

## 目的

PIAを実施する前に答えるべき質問に答える：「そもそもPIAが必要か？」必要な場合、どの種類が必要で、何が障害になっているか。

出力は4つの分類のいずれか：
- **進行可** — PIAは不要。標準的な安全管理措置を適用。
- **PIA必要** — PIA（影響評価）を実施してから、または並行して進行。
- **要再設計** — プライバシーポリシーとの矛盾があるか、適法根拠がない。進行前に再設計が必要。
- **停止** — 現在の設計では法令上進行不可。根本的な見直しが必要。

## 処理活動の把握

ユーザーから以下を確認：

1. **何をするか:** 処理活動の概要
2. **誰のデータか:** 対象者（顧客、従業員、ユーザー等）
3. **どのデータか:** 個人情報の項目
4. **なぜするか:** 利用目的

## APPI固有のトリアージチェック

### チェック1: 要配慮個人情報の取得（第20条第2項）

以下に該当する場合は 🔴 **PIA必要 + 弁護士確認**：
- 病歴、犯罪の経歴、犯罪により害を被った事実
- 人種、信条、社会的身分
- 身体障害・知的障害・精神障害等
- 健康診断の結果、医師の指導・診療情報
- 刑事事件の手続き、少年の保護事件の手続き

### チェック2: マイナンバーの取扱い

マイナンバー（特定個人情報）を含む場合：
- 🔴 利用目的が法定の範囲内か確認必須
- → `/privacy-legal-jp:my-number-assessment` に引き渡し

### チェック3: 越境移転（第28条）

外国にある第三者への提供が含まれる場合：
- 🟠 越境移転の適法根拠の確認が必要
- → `/privacy-legal-jp:cross-border-transfer-assessment` に引き渡し

### チェック4: 個人関連情報の第三者提供（第31条）

Cookie、広告ID等の個人関連情報を第三者に提供し、提供先で個人データ化が想定される場合：
- 🟠 確認義務の履行が必要
- → `/privacy-legal-jp:kojin-kanren-joho-check` に引き渡し

### チェック5: 仮名加工情報/匿名加工情報の区分

データを加工して利用する場合：
- 仮名加工情報：内部利用のみ（第三者提供禁止）
- 匿名加工情報：PPC届出＋公表が必要
- 個人関連情報：第31条の規制対象
- 統計情報：個人情報に該当しない場合は規制なし

### チェック6: 外部送信規律

電気通信事業者に該当し、タグ・Cookie等で外部送信を行う場合：
- 🟠 通知・公表等の措置が必要
- → `/privacy-legal-jp:telecom-external-transmission-check` に引き渡し

### チェック7: ポリシー整合性

プラクティスプロファイルの `## プライバシーポリシー等の公表事項` と照合：
- 利用目的がポリシーに含まれているか
- 第三者提供がポリシーに記載されているか
- 矛盾がある場合はポリシーの更新を先行

## 弁護士確認ゲート

利用者が「法務部員等」または「その他」の場合：

> ⚖️ **弁護士確認ゲート:** トリアージの分類判定は法的判断を含みます。特に「進行可」の判定については、弁護士の確認を得てから進行してください。

## 意思決定ツリー

> **次のステップは？選んでください：**
> 1. **PIA作成** — `/privacy-legal-jp:pia-generation` でPIAを作成
> 2. **越境移転評価** — `/privacy-legal-jp:cross-border-transfer-assessment`
> 3. **個人関連情報チェック** — `/privacy-legal-jp:kojin-kanren-joho-check`
> 4. **ポリシー更新** — `/privacy-legal-jp:policy-monitor` でポリシーの更新を検討
> 5. **エスカレーション** — [エスカレーション先]に相談メモを作成
> 6. **その他**

## このスキルが行わないこと

- PIAの作成は行わない — 分類と条件の提示まで
- データフローの技術的な検証は行わない
- プロダクトの設計変更は行わない — 再設計の必要性の指摘まで
- GDPR DPIA（データ保護影響評価）の要否判定は行わない

## 免責事項

本トリアージはAPPIに基づく処理活動のリスク分類の支援であり、個人情報保護委員会の公式な判断を代替するものではありません。「進行可」の判定はPIAが不要であることを保証するものではなく、弁護士の確認を得てから進行してください。
