# /client-comms-log

1. 案件IDを要求（提供されていなければプロンプト）。
2. フラグに応じてルーティング：
   - `--add`（デフォルト）: 方向、手段、学生、概要、アクション項目、フォローアップ期日を記録。確認後に追記。
   - `--read`: 直近N件のエントリを表示。
   - `--summary`: 1段落の要約。
   - `--patterns`: 未回答の連絡、フォローアップ漏れ、連絡間隔の分析。監督向け。
3. 連携：期限が判明した場合は `/legal-clinic-jp:deadlines --add` を提案。

```
/legal-clinic-jp:client-comms-log [案件ID]
```

# 依頼者対応記録

## 目的

記録を残す4つの理由：

1. **弁護過誤の防御。** 依頼者が「聞いていない」と主張した場合、日付入りの記録が回答。
2. **引継ぎの継続性。** 次の学期の学生が記録を読み、同じ質問を繰り返さない。
3. **監督の可視化。** 6週間にわたる5件の未回答は、個々の学生が自覚しないパターン。
4. **記録保持義務。** 法科大学院クリニックは完全な依頼者ファイルを維持する義務がある。

軽量。追記型。学生は毎回の連絡後に2-3行のエントリを記入。

## エントリの形式

```markdown
### [YYYY-MM-DD HH:MM] [方向: 着信/発信] [手段: 電話/メール/対面/書面/LINE]

**担当学生:** [学生名]
**概要:** [2-3行で何を話したか/やり取りしたか]
**依頼者の状況:** [依頼者の反応、懸念事項があれば]
**アクション項目:**
- [ ] [次にやるべきこと]
- [ ] [フォローアップ期日: YYYY-MM-DD]
**指導弁護士への報告事項:** [あれば]
```

## 弁護士法第72条ゲート

連絡記録の作成自体は法律事務に該当しませんが、依頼者への法的助言を含む連絡は指導弁護士の監督下で行う必要があります。記録に法的助言の内容が含まれる場合は `【指導弁護士確認済み】` マークを付します。
