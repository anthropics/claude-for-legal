# /cold-start-interview

1. `~/.claude/plugins/config/claude-for-legal/regulatory-legal-jp/CLAUDE.md` を確認。以前のキャッシュパス（`~/.claude/plugins/cache/claude-for-legal/regulatory-legal-jp/*/CLAUDE.md`）に設定済みファイルがあり、コンフィグパスにない場合はコピー。`--check-integrations` の場合はインタビューをスキップし、Part 0 の接続確認のみ再実行して `## 連携ツール` テーブルを更新。
2. 以下のインタビューワークフローを使用。Part 0（役割＋連携確認）→ 監視対象設定 → 業法マッピング → 重要度閾値。
3. ポリシーフォルダを接続。ポリシーをインデックス。
4. `~/.claude/plugins/config/claude-for-legal/regulatory-legal-jp/CLAUDE.md` に監視リスト＋重要度閾値を書き込み（親ディレクトリは必要に応じて作成）。

連携確認時：MCPツール呼び出しが実際に成功した場合のみ ✓ を報告。`.mcp.json` の宣言だけで ✓ を報告しないこと。

## 目的

すべての省庁が常時情報を発信しています。その大半はあなたに関係ありません。このインタビューは、どの規制当局を監視し、何が「重要」かを学習することで、モニターがノイズではなくシグナルを検出できるようにします。

## コールドスタートチェック

`~/.claude/plugins/config/claude-for-legal/regulatory-legal-jp/CLAUDE.md` を読む：
- **存在しない** → インタビューを開始。
- **`<!-- SETUP PAUSED AT: -->` を含む** → ユーザーに挨拶し、そのセクションから再開を提案。
- **`[PLACEHOLDER]` を含むが一時停止コメントなし** → テンプレートが未完了；新規開始または途中からの再開を提案。
- **設定済み（プレースホルダーなし、一時停止コメントなし）** → 設定済み；`--redo` でなければスキップ。

テンプレート構造は `${CLAUDE_PLUGIN_ROOT}/CLAUDE.md` にあります — セクションの骨格として使用。

## 共有会社プロファイルの確認

`~/.claude/plugins/config/claude-for-legal/company-profile.md` を確認。

- **存在する場合:** 読み込み、1行で確認表示。確認済みなら会社の質問をスキップし、プラグイン固有の質問へ。
- **存在しない場合:** 会社プロファイルの質問を実施し、共有プロファイルに書き込み。

## インタビュー開始前

> **`regulatory-legal-jp` は、規制動向を追跡し、ポリシーギャップを評価し、コンプライアンス義務を管理する方のためのプラグインです。** 別の領域をお探しですか？ `/legal-builder-hub-jp:related-skills-surfacer` をお試しください。
>
> **2分**で、役割、プラクティス設定、主要な規制当局を設定できます。**15分**あれば、監視リスト、重要度閾値、フィード設定、ポリシーライブラリインデックス、業法マッピング、パブコメ対応設定をすべて完了します。
>
> クイックとフルのどちらにしますか？（いつでも `/regulatory-legal-jp:cold-start-interview --full` でアップグレードできます。）

## インタビューの進め方

- **バッチサイズ — サブパートを数える。** 1回のターンで2-3件の回答可能なプロンプトまで。
- **実質的な回答を待つ。** タイピングが必要な質問では「この質問は入力が必要です — お待ちします。」と伝えて待機。
- **一時停止と再開。** 「pause」で進捗を保存。`<!-- SETUP PAUSED AT: [section] -->` を書き込み。

## インタビュー

### Part 0: 役割と連携確認

1. **利用者の役割を確認:**
   - 弁護士（企業内弁護士含む）— 日本弁護士連合会登録
   - 法務部員（弁護士資格なし、顧問弁護士あり）
   - その他（弁護士資格なし、顧問弁護士なし）

2. **連携ツールの確認:**
   - e-Gov法令検索API（`https://elaws.e-gov.go.jp/api/1/`）に接続テスト
   - 官報RSS（`https://kanpou.npb.go.jp/`）に接続テスト
   - 省庁別報道発表RSSの確認
   - Slack MCP の接続確認
   - Google Drive MCP の接続確認

### Part 1: 監視対象の設定（クイック・フル共通）

> どの省庁・規制当局を監視しますか？業種から推測しますので、主な事業内容を教えてください。

主要な所管省庁の候補：

| 厚生労働省 | 労働基準法、労働者派遣法 | mhlw.go.jp RSS |

### Part 2: 業法マッピング（フルのみ）

> 御社の事業活動に適用される業法（業種別の規制法）を確認します。業種、主な事業内容、現在取得している許認可を教えてください。

確認事項：
- 適用される業法（例：金融商品取引法、宅建業法、建設業法、電気通信事業法）
- 取得済みの許認可・届出
- 定期報告義務の有無
- 行政検査への対応体制

### Part 3: 重要度閾値（フルのみ）

> 規制変更がどの程度重要であれば対応が必要ですか？

三段階を確認：
- **対応必須（🔴）:** 即時対応が必要な変更
- **要確認（🟡）:** 評価して判断する変更
- **参考情報（🟢）:** 記録のみ、対応不要

### Part 4: ギャップ対応プロセス（フルのみ）

> 規制変更が見つかった場合のエスカレーション・対応フローを教えてください。

確認事項：
- トリアージ担当者
- ポリシー更新担当者
- ギャップの管理方法（チケットシステム、スプレッドシート等）
- 重大ギャップのエスカレーション先
- 稟議フロー

### Part 5: フィード設定（フルのみ）

> どの頻度でフィードを確認しますか？

確認事項：
- チェック頻度（毎日 / 毎週）
- ダイジェストの配信先（Slack チャンネル / ファイル出力）
- 審議会のモニタリング対象

### Part 6: ポリシーライブラリ（フルのみ）

> 社内規程・ポリシーはどこに保管していますか？フォルダパスまたはリンクを教えてください。

インデックス対象：
- 各ポリシーの名前、ファイルパス、最終更新日、担当者

## クイック完了時

> 完了です。コマンドを使い始められます。重要度閾値、ダイジェスト頻度、ポリシーライブラリ構成にはデフォルト値を使用しています。スキルの出力が実務に合わないと感じた場合は、通常デフォルト値の調整が必要です。いつでも `/regulatory-legal-jp:cold-start-interview --full` でフルインタビューを実行できます。

## フル完了時

書き込み前に、スキップされた質問やプレースホルダーで残っている項目をすべて列挙し、ユーザーに確認。
