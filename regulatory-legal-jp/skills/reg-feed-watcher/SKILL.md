# /reg-feed-watcher

1. `~/.claude/plugins/config/claude-for-legal/regulatory-legal-jp/CLAUDE.md` → 監視リスト、重要度閾値、フィード設定を読み込み。
2. 以下のワークフローを使用。
3. 各フィードを取得。重要度でフィルタリング。
4. 出力：新着を重要度ティアごとに分類。

---

## 目的

フィードを取得し、重要度でフィルタリングし、残ったものを出力します。フィルタが価値です — フィルタリングなしのフィードはノイズです。

## コンテキスト読み込み

`~/.claude/plugins/config/claude-for-legal/regulatory-legal-jp/CLAUDE.md` → 監視リスト、重要度閾値、フィード設定、ダイジェスト出力パス。

## ワークフロー

### Step 0: カバレッジチェック（取得前）

監視リスト＋フィード設定を確認し、カバレッジギャップがある場合は表示：

> **カバレッジギャップ検出:** 監視リストに[省庁]がありますが、フィードが[N]件のみです。`/regulatory-legal-jp:cold-start-interview --redo` で更新するか、CLAUDE.md を直接編集してください。

### Step 1: 取得

すべての設定済みフィードティアから取得。

**Tier 1 — 無料フィード（常時有効）**

監視リストの各規制当局について：

- **e-Gov法令検索API** (`https://elaws.e-gov.go.jp/api/1/`) — 法令名、法令番号、改正日で検索。法令の新規制定・改正を検出。
- **官報RSS** (`https://kanpou.npb.go.jp/`) — 法律・政令・省令・告示・通達の公布を検出。法律の施行日、経過措置を確認。
- **省庁別報道発表RSS** — 各省庁のRSSフィードを取得・パース。パブリックコメント募集、ガイドライン公表、行政処分を検出。

主要フィードソース：

| 省庁 | フィードURL | 取得内容 |
|---|---|---|
| 金融庁 | fsa.go.jp/news/ | 法令改正、ガイドライン、行政処分 |
| 経産省 | meti.go.jp/press/ | 政策発表、報告書、パブコメ |
| 個人情報保護委員会 | ppc.go.jp/news/ | ガイドライン、Q&A、行政上の対応 |
| 公正取引委員会 | jftc.go.jp/houdou/ | 排除措置命令、課徴金、ガイドライン |
| 消費者庁 | caa.go.jp/notice/ | 措置命令、景品表示法関連 |

**Tier 2 — 有料フィード（設定済みの場合）**

- **Westlaw Japan MCP:** 前回チェック日以降の更新を照会。
- **その他の有料規制情報サービス。**

ティア間で重複排除 — 同じ文書が複数ソースに出る可能性あり。

**無断補完の禁止。** フィード取得で特定の省庁の結果が少ない場合、見つかったものを報告して停止。ウェブ検索やモデル知識で補完しない：「フィードチェックで[省庁]から[N]件を検出。カバレッジが薄いようです。選択肢：(1) 期間を広げる、(2) 別のフィードを試す、(3) ウェブ検索する（結果は `[ウェブ検索 — 要確認]` タグ付き）、(4) ここで停止。どうしますか？」

**Tier 3 — 手動入力**

ユーザーが規制テキストをペーストした場合：単一アイテムとして処理、Step 2 に直行。

### Step 2: 分類

各アイテムに重要度ティアを割り当て：

| アイテム種別 | 閾値との照合 |
|---|---|
| 法律・政令の改正（公布済み） | 通常「対応必須」 |
| 省令・規則の改正 | 通常「対応必須」 |
| パブリックコメント募集 | 通常「要確認」— 意見提出期限を必ず記録 |
| ガイドライン・指針の公表・改定 | 「要確認」 |
| 通達・行政指導 | 「要確認」— 法的拘束力なしだが実務上重要 |
| 行政処分（自社業界） | 「対応必須」 |
| 行政処分（関連業界） | 「要確認」 |
| 審議会報告書・中間とりまとめ | 「要確認」— 法改正の上流シグナル |
| 報道発表・スピーチ | 「参考情報」またはスキップ |

**パブコメ期限の処理:**

パブコメとして分類されたすべてのアイテムについて：
- 意見提出期限を抽出
- パブコメトラッキングが有効な場合：`~/.claude/plugins/config/claude-for-legal/regulatory-legal-jp/comment-tracker.yaml` に追記（ステータス「未決定」）
- 出力エントリに意見提出期限を含める

### Step 3: エンリッチ

参考情報ティア以上の各アイテムについて：
- 1行サマリー（何が変わったか）
- なぜ関係するか（関連性のフック）
- ソースへのリンク
- 施行日またはパブコメ期限

参考情報アイテムは個別にサマリーしない — 件数のみ。

## ハンドオフ

- **policy-diff へ:** 「対応必須」アイテムでポリシーへの影響がある場合 → 差分実行を提案。
- **gap-surfacer へ:** 差分でギャップが見つかった場合 → トラッキング。
- **comments へ:** パブコメとして分類された場合 → 意見提出期限を自動記録。
- **shinkyuu-taishohyo へ:** 法令改正の場合 → 新旧対照表の生成を提案。

## 意思決定ツリーで締めくくる

CLAUDE.md `## 出力設定` に従い、意思決定ツリーで締めくくります。

## 弁護士確認ゲート

フィード監視・分類自体には弁護士確認ゲートは不要です。ただし、分類結果に基づく具体的なコンプライアンス上の助言を行う場合は、`## 利用者情報` の役割を確認し、弁護士以外のユーザーにはゲートを適用します。

## 免責事項

規制フィードの分類はAIによる暫定的な評価です。法的助言ではありません。重要な規制変更については、必ず弁護士に確認してください。
