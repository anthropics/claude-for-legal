# /study-plan

1. `~/.claude/plugins/config/claude-for-legal/law-student-jp/CLAUDE.md` を読み込み → 受験区分、試験日程、弱点科目、目標学習時間/日、利用予備校。
2. `~/.claude/plugins/config/claude-for-legal/law-student-jp/study-plan.yaml` が存在すれば読み込み。
3. 以下のフレームワークを適用する。
4. フラグによるルーティング：
   - `--build`（計画が存在しない場合のデフォルト）：入力ゲートを通過（試験区分、科目、時間/週、休日、学習方法）。フェーズ構造 + 最初の2週間の日次スケジュールを構築。`study-plan.yaml` に書き込み。
   - `--update`（計画が存在する場合のデフォルト）：`session_history` を再読み込みし、科目の優先度と `weekly_hours` を調整、次の期間の日次スケジュールを記入。
   - `--status`：今日/今週の予定、得点推移、伸び悩み科目、各科目の次回セッション。
   - `--cram`：直前モードを強制 — 高頻出分野への集中、短答式の量的演習、最終2-3日のテーパリング。
5. 書き込み前に：計画を文章で要約し、受講生に確認。回答に基づいて調整。
6. 常に週当たりの学習時間を受講生の生活状況と照合する。過大な計画は失敗する。

---

## 目的

「何を勉強すべきか分からない」まま机に向かうことが、何週間も無駄にする原因。このスキルは計画を立てる — 試験までの週数、1日のセッション、週ごとの科目配分、セッションの種類 — そして受講生が実際にセッションを進めるにつれて適応する。カレンダーの出力ではなく、生きた計画。

下流のスキル（短答式演習、フラッシュカード、ドリル、論文練習）に共有スケジュールを提供し、セッションを開くたびに「今日は何を勉強しますか？」と聞かれないようにする。

## 信頼性の規律

計画は意見であり、法規範ではない。推定値は明示する：

- **科目別の所要時間の推定：** 一般的な指針（典型的な予備校カリキュラムの配分に基づく）。推定値であることを明示 — 受講生の実際のペースは異なる。
- **科目の重み付け：** 受講生自身が申告した弱点科目とセッション履歴から導出。確信あり。
- **直前モードでの高頻出分野の優先順位付け：** 過年度の司法試験・予備試験の出題傾向に基づく。「これは必ず出る」という主張には `[過去の出題頻度であり予測ではない]` を付す。

## コンテキスト読み込み

`~/.claude/plugins/config/claude-for-legal/law-student-jp/CLAUDE.md`：
- 受験区分（司法試験/予備試験）、試験日程
- 在学中の科目（非受験用途の場合）
- 弱点科目（短答式、論文式）
- 利用予備校
- 目標学習時間/日

`~/.claude/plugins/config/claude-for-legal/law-student-jp/study-plan.yaml` が存在すれば — 拡張し、上書きしない。

## ワークフロー

### ステップ 1：何のための計画か

> 何の計画を立てますか？
>
> 1. **司法試験**（7月実施 — 短答式+論文式を4日間で実施）
> 2. **予備試験**（5月短答式 → 7月論文式 → 10月口述式）
> 3. **法科大学院の定期試験**
> 4. **学期全体の学習ペース管理**

(1) 司法試験：プラクティスプロファイルから試験日を読み取り、確認。日程が未登録なら確認。
(2) 予備試験：短答式・論文式・口述式それぞれの日程を確認。現在どの段階を目指しているか。
(3) 定期試験：科目、日程、形式を確認。
(4) 学期管理：学期末日をアンカーとして確認。

### ステップ 2：入力 — 一つずつ確認、各回答を待つ

**確認して待つ。** すべての質問を一度に出して先に進まない。

- **試験日：** 確認済みか？
- **対象科目：** 司法試験の場合、7法律科目（憲法、行政法、民法、商法、民事訴訟法、刑法、刑事訴訟法）＋選択科目。予備試験の場合はこれに一般教養を加える。受講生に確認 —「追加・除外すべき科目はあるか？」
- **得意科目：** 優先度を下げる。復習はするが、集中的な演習は少なめ。
- **苦手科目：** 優先度を上げる。より多くのセッションを配分。
- **週当たりの学習時間：** 現実的な数字 — 理想ではない。「30時間できます」と「30時間を8週間続けます」は別物。実際に維持できる時間を確認。
- **生活状況の確認 — 必ず実施する。** 受講生が時間を申告した後、以下を確認する（一問ずつ — 省略しない）：

  > [N]時間/週とのことですが、計画を立てる前に教えてください — 仕事（週何時間）、家庭の事情（育児、介護）、通学、アルバイト、その他の活動は？計画は生活に合わせるべきで、生活を計画に合わせるのではありません。守れない計画は、軽めでも守れる計画より悪い結果になります。

  回答を待つ。申告時間と生活状況を照合する：

  > それは勉強日 [N] 日で1日あたり約 [X] 時間、[仕事+家庭+通学+その他] の上に積む計算です。経験上、それは [現実的/やや厳しい/持続不可能] です。計画を立てる前に時間/週の目標を調整しますか？それとも第1週の様子を見ますか？

  プラクティスプロファイルに目標時間が既に記録されていてもこのステップを省略しない。プロファイルは受講生が言ったことを記録している；生活状況の確認はそれが持続可能かを確認する。より少ない数字が出た場合、そちらを使い、`confidence_flags` ブロックに調整を記録。

  受講生が生活状況の共有を断った場合（「そのまま作って」）、尊重する — ただし `confidence_flags` に記録：「生活状況の確認を辞退；[N]時間/週が持続可能と仮定。第2週終了時点で達成率が [X]% 未満なら見直し。」

- **学習方法の選好：** 複数選択。短答式演習/論文答案練習/フラッシュカード/まとめノート作成/ドリル/基本書通読。受講生が実際にやると言った方法に重みを置く。
- **週あたりの休日：** 休息日は重要。7日中7日勉強する計画は第3週で破綻する。

### ステップ 2.5：補完か代替か（予備校利用者）

`~/.claude/plugins/config/claude-for-legal/law-student-jp/CLAUDE.md` → `利用予備校` が**伊藤塾**、**LEC**、**辰已法律研究所**、**アガルート**、**資格スクエア**、またはその他の体系的な予備校（`独学` や `N/A` ではない）の場合、受講生には既に予備校のカリキュラムがある。このスキルの計画は二つの役割のいずれかを選ぶ必要がある — 予備校と並行してフルカリキュラムを走らせると受講生は消耗する。

一つの質問を出し、待つ：

> プロファイルによると [伊藤塾/LEC/辰已/アガルート/資格スクエア] を利用中ですね。予備校には科目・タスクが日単位で組まれたカリキュラムがあります。この計画の役割を選んでください：
>
> 1. **補完。** 予備校が主カリキュラム。この計画は穴を埋めます：苦手科目の追加演習、弱点論点のドリル、フラッシュカードの反復。予備校のカリキュラムを再構築しません。
> 2. **代替。** 予備校のカリキュラムに従っていない（ペースが合わない等の理由で）。科目、時間、フェーズ、スケジュールをすべてこの計画で構築します。
>
> 両方は選ばないでください。二つのフルカリキュラムを同時に走らせると第4週で破綻します。

回答を待つ。yamlに `prep_course_mode: supplement | replace` として記録。

**補完**の場合：日次スケジュールは軽め — 弱点科目のドリルと的を絞った演習のみ追加し、予備校の内容と重複しない。`confidence_flags` に記録：「補完モード — この計画は [予備校名] の主カリキュラムに沿っていることを前提とする。予備校で遅れが出たら報告してください、再計画します。」

**代替**の場合：以下の仕様でフル計画を構築。

利用予備校が `独学` または `N/A` の場合、このステップを省略。

### ステップ 3：スケジュール構築

今日の日付から試験日までの週数を計算する。

**通常モード（4週間以上）：**
- 週数をフェーズに分割：
  - **基礎期**（全体の約40%）：基本書通読、条文素読、基礎的な短答演習。一科目あたり3-5日、まとめノート作成とフラッシュカードを組み合わせる。
  - **論文期**（約30%）：答案構成の練習、論証パターンの確立、過去問演習。全科目をローテーション。
  - **短答期**（約20%）：肢別問題集の大量演習、過去問、弱点科目の補強。
  - **直前期**（約10%）：総まとめ、弱点集中、模試。本番形式での演習。
- 科目の重み付け：苦手科目に得意科目の約2倍の時間を配分。
- 日次スケジュール：科目、学習方法、時間。受講生の実際の生活に余裕を残す。

**直前モード（4週間未満）：**
- フラグを立てる：「試験まで4週間を切っています。これは直前モード — 全範囲のカバーより高頻出分野を優先します。カバーできない範囲が出ます。この時点ではそれがトレードオフです。」
- 高頻出分野の優先：過去の出題傾向で頻出の論点（民法の総則・物権・債権各論、刑法の各論、憲法の人権等）に時間を集中。出題頻度の低い分野は最低限のカバー。
- 日次スケジュール：短答式ブロックを毎日（量が重要）、論文答案練習を隔日、模試を週1回。
- 最後の2-3日は睡眠とテーパリング。試験前日にハードな演習を入れない。これは実証済み — 前夜に詰め込む受験生は成績が下がる。

### ステップ 5：受講生への確認

**ヘッダー — チャット内の提示および計画文書に必ず記載。** 要約の最初の行（および `study-plan.md` 補助ファイルの最初の行）はプラグイン設定 `## Outputs` のヘッダーをそのまま使用：

```
学習ノート — 法的助言ではありません
```

ヘッダーはYAML自体には入れない（データファイルのため）が、受講生に見せる文章要約とYAMLの横に保存する人間可読な計画文書には記載する。免責の付け足しではなく、出力の性格表示。省略・言い換え・移動しない。

計画を文章で要約（生のYAMLではなく）し、ヘッダーを冒頭に置いて保存前に提示：

> 学習ノート — 法的助言ではありません
>
> 計画を立てました。[試験] まで [X] 週間。[Y] 時間/週、[Z] 日間。苦手科目（[科目名]）に2倍の時間を配分。4つのフェーズ：基礎期 [日付] まで、論文期 [日付] まで、短答期 [日付] まで、直前期 最後の [N] 日間。最初の2週間は日次スケジュールを入れました。それ以降は週単位の配分 — セッションを進めるにつれて日次スケジュールを埋めていくので、計画は実際の進捗に適応します。
>
> この計画はどうですか？ 意欲的すぎますか？ 軽すぎますか？ 科目の漏れはありますか？

回答に基づいて調整。その後書き込み。

## 計画の適応

各セッション後（短答式演習、フラッシュカード、ドリル、論文練習を通じて）、対応するスキルが `session_history` に追記：

```yaml
session_history:
  - date: 2026-07-01
    subject: 民法
    type: 短答演習
    n_questions: 20
    score: 14
    weak_subtopics: [詐害行為取消権, 債権者代位権]
```

次回の `/law-student-jp:study-plan --update` 実行時（または他のスキルが計画の陳腐化を検知した時）：
- 継続的に低得点の科目は `priority` と `weekly_hours` を引き上げ。
- 科目内の弱点論点は、その科目の次回セッションにフラグ付け。
- 受講生が遅れている場合（予定セッションが履歴に出てこない）：カバー範囲を圧縮するか、ギャップを示して確認。
- 受講生が先行している場合：苦手科目の深掘りに時間を開放。

## モード

`--build`（デフォルト）— 新規計画
`--update` — session_history を再読み込みし重み付けを調整、次の日次スケジュールを記入
`--status` — 今日/今週の予定、得点推移、伸び悩み科目
`--cram` — 4週間以上あっても直前モードを強制（受講生の上書き）

## 連携

- `/law-student-jp:session <科目> <n>` はこの計画の `session_history` に結果を書き込む。
- `/law-student-jp:bar-prep-questions` は計画を読んで今日の科目を判断する。
- `/law-student-jp:flashcards` は `--session <n>` で結果を計画に追記。
- `/law-student-jp:socratic-drill` および `/law-student-jp:irac-practice` のセッション完了も追記。

## このスキルがやらないこと

- **合格を保証しない。** 計画は足場。勉強するのはあなた。
- **出題を予測しない。** 直前モードは過去の出題頻度を使う；高頻出 = 出題確定 ではない。
- **予備校のスケジュールを置き換えない（補完モードの場合）。** 伊藤塾/LEC/辰已/アガルート/資格スクエアを利用中なら、この計画は補完として使える — 二つのフルカリキュラムを同時に走らせない。
- **生活を管理しない。** 利用可能な時間はあなたが申告するもの。過大に申告すれば第2週で計画が破綻する。正直に申告すること。
