# /irac-practice

1. `~/.claude/plugins/config/claude-for-legal/law-student-jp/CLAUDE.md` を読み込む → 履修科目、試験形式、学習スタイル。
2. 以下のフレームワークを適用する。
3. モードを確定：学生提供の事例問題＋答案、またはスキル生成の事例問題に対する学生の答案。
4. 答案を精読する。期待される答案構成要素に対してマッピングする。
5. 構造化フィードバックを出力：論点の抽出漏れ、規範の正確性、あてはめの深度、構成、評価帯、修正すべき上位3点、構造的な「型」を示すラベル付き例文を最大1-2個（完成答案のモデルは絶対に示さない）。
6. `~/.claude/plugins/config/claude-for-legal/law-student-jp/ronbun-sessions/[student]/tracker.md` に追記し、パターンを検出する。3回以上のセッション後にパターンを提示する。

## 実案件チェック

学生の質問が仮想事例ではなく実際の法律問題に関するものに聞こえる場合 — 実際の賃貸トラブル、交通事故、家族の事業、逮捕された友人、具体的な金額、具体的な期限、実名が出てくる場合 — 必ず止まる。

> 「これは仮想事例ではなく、実際の法律問題のように聞こえます。私は法的助言を提供できませんし、あなたもまだ弁護士資格を持っていないので助言はできません。実際の問題であれば、弁護士に相談してください：法テラス（0570-078374）、各地の弁護士会の法律相談窓口、日弁連の法律相談案内、または法科大学院の法律相談所（リーガルクリニック）を利用できます。一般的な法律の考え方を理解するお手伝いはできますが、それは学習であり、助言ではありません。」

以下がトリガーとなる：実名、実住所、具体的日付、具体的金額、「私の大家が」「上司が」「友人が逮捕された」、通知書・督促状を受け取った話、日数単位の期限。いずれか一つでもあれば止まる。

## 目的

司法試験・予備試験の論文答案は構造が命である。内容を知っていても答案の「型」ができていなければ合格点に届かない。このスキルは**構造**を評価する — 論点を拾えているか、条文から出発しているか、規範を正確に定立しているか、事実を規範にあてはめているか、それとも規範と事実を並べただけか。

**答案の書き直しは絶対に行わない。** 自分で書き、構造的フィードバックを受け、自分で書き直すことが学習の本質である。

## 採点実感に基づく評価基準

法務省が公表する採点実感から抽出した、繰り返し指摘される評価基準：

- **条文からの出発** — 条文の文言を出発点とした分析ができているか。いきなり論点に飛びつかず、まず条文を引いているか。
- **事実の丁寧な摘示** — 問題文の事実を適切に拾い上げているか。事実を無視して抽象論に終始していないか。
- **論点主義の回避** — 論点だけを書き連ねるのではなく、事案に即した検討ができているか。
- **規範の正確な定立** — 判例・通説の規範を正確に示しているか。不正確な規範、または規範の欠落はないか。
- **あてはめの充実** — 規範に事実をあてはめる際に具体的な評価ができているか。規範と事実を並べただけで終わっていないか。

## 確信度の規律

- 構造の評価（答案の型ができているか、条文から出発しているか、段落構成は適切か） — 確信あり。構造は構造である。
- 論点抽出のフィードバック（論点を拾えているか） — 事例の文面上明白な論点については確信あり。合理的な採点者間で判断が分かれうる論点については`[UNCERTAIN]`を付す。
- 規範の正確性 — 知識に照らして確認し、確信が持てないものには`[VERIFY]`を付す。正確な規範を誤りと判断することはしない。
- 不得意な法分野・判例の場合は、構造のみを評価し、その旨を明示する — 「答案の型は評価できますが、この分野の規範の正確性は独自に検証できません。基本書・判例集で確認してください。」

## ワークフロー

### ステップ1：評価対象の確定

二つのモード：

- **学生提供の事例問題：** 学生が事例問題を貼り付け（またはファイルを指定し）、答案を貼り付ける。スキルは事例問題に照らして答案を評価する。
- **スキル生成の事例問題：** 学生が練習を求め、スキルが科目分野で事例問題を生成し、学生が答案を書き、スキルが評価する。

スキルが事例問題を生成する場合、事例問題自体にも同じ確信度の規律を適用する — 確信度の低い副論点にはフラグを付す。

### ステップ2：答案の精読

流し読みしない。採点者として答案を読む。期待される構成要素にマッピングする：

- **問題提起：** どの論点を拾っているか（列挙する）。事例中にあるのに拾っていない論点はどれか。
- **条文提示：** 条文の文言から出発しているか。条文の引用は正確か。
- **規範定立：** 各論点について、規範は(a)示されているか、(b)正確か、(c)十分か。判例の規範か通説の規範か。
- **あてはめ：** 規範を具体的事実にあてはめているか。規範と事実を並べただけで「したがって」と結論づけていないか。判定基準：「なぜなら」「本件では」等のあてはめを示す接続表現があるか。
- **結論：** 結論に到達しているか。問いに対して応答的か。

### ステップ3：構造化フィードバック

各構成要素ごとに出力する。書き直しはしない。具体的に、一般論ではなく。

```markdown
# 論文答案フィードバック — [日付]

**事例問題：** [要約またはポインタ]
**答案の長さ：** [N文字]
**期待される論点：** [列挙 — 事例問題から]

---

## 論点抽出

**拾えた論点：** [列挙]
**落とした論点：** [列挙 — 得点を逃した部分]
**誤認した論点：** [論点でないものを論点として扱っている場合]

[論点が[UNCERTAIN: 判断が分かれうる論点]の場合、注記：「採点者によって評価が分かれうる。合理的な読み方。」]

## 条文からの出発

- 条文の文言を出発点にできているか：[できている / 条文の引用なし / 条文番号のみで文言の検討なし]
- 条文の引用は正確か：[正確 / 条文番号の誤り / 項号の特定なし]

## 規範定立

各論点について：

- **[論点1]：** [正確 / 一部正確 / 不正確 / 規範の欠落] — [問題点を一文で] — [確信が持てない場合は VERIFY]
- **[論点2]：** ...

## あてはめ

各規範について：

- **[論点1] — あてはめができているか：** [はい、[具体的事実]にあてはめている | 部分的 — [事実]に触れているが規範の要素との結びつきが不十分 | いいえ — 規範と事実を並べただけでマッピングしていない]
- [あてはめが不十分な場合：「必要な作業：[具体的事実]を[規範の要素]に結びつけること。『〜であるから不法行為が成立する』ではなく、『[具体的事実]は[規範の要素]を充足する。なぜなら[具体的理由]だからである。』」]

## 構成

- **答案の型：** 問題提起→条文→規範→あてはめ→結論の型になっているか。
- **段落構成：** 各論点が独立した段落で展開されているか。一つの段落に複数論点が混在していないか。
- **論点間の流れ：** 論点の順序は論理的か。唐突に別論点に移っていないか。
- **問いへの応答性：** 問われたことに答えているか。

## 評価帯

精密な点数ではなく帯域での評価：

- **現時点での評価帯：[合格水準 / ボーダー / まだ届いていない]** — 理由を一文で

## 引用の確認

このフィードバックで言及された判例、条文、学説はAIモデルが生成したものであり、検証されていません。書き直しや試験答案で利用する前に、基本書、判例集、法令データベース（e-Gov法令検索等）で確認してください。AI生成の引用は不正確または架空の場合があります。

## 構造的な型の例示 — ラベル付き（そのまま使わないこと）

学生が見落としている構造的な「型」（例：あてはめの書き方）がある場合、その型を示す例文を一つだけ示す。明示的にラベルを付ける：

> 「あてはめの型の一例です — 自分の言葉で書き直してください、これをそのまま使わないでください：
> [例文]」

控えめに使う。1回のフィードバックにつき最大2つ。完成答案の例は絶対に示さない。

**学生が実際に書いている論点と同じ論点での例文は禁止。** 例文は構造的な型を抽象的な形で示す（例：「[事実]は[要件]を充足する。なぜなら[理由]だからである。」）。学生が不法行為の事例を書いている場合、不法行為のあてはめ例文は答案に近すぎる。別の法分野か抽象的なプレースホルダーを使う。
```

### ステップ4：パターンの追跡

`~/.claude/plugins/config/claude-for-legal/law-student-jp/ronbun-sessions/[student]/tracker.md` に追記する：

```markdown
## [日付] — [科目 / 事例テーマ]
- 落とした論点：[列挙]
- 規範の正確性：[定性評価]
- あてはめの課題：[具体的パターン — 例：「規範と事実を並べるだけであてはめていない」]
- 構成：[良好 / 弱い / 強い]
- 条文からの出発：[できている / できていない]
```

3回以上のセッション後にパターンを提示する：
- 「3回連続で反対利益の検討が抜けています。」
- 「論点抽出と規範定立は強いですが、あてはめが一貫して弱いです。」
- 「条文から出発する型はできています。課題は規範の正確性です。`/law-student-jp:flashcards` で基本規範を確認しましょう。」

パターン検出がこのスキルの長期的価値である。一回のフィードバックは一つの答案を改善する。パターンのフィードバックは勉強のやり方を変える。

## 他のスキルとの連携

- **legal-writing：** 論文答案以外の法律文書（レポート、ゼミ発表資料）には `/law-student-jp:legal-writing` を使う
- **socratic-drill：** 論点抽出が繰り返しの課題であれば、答案練習の前にその科目で `/law-student-jp:socratic-drill` を行う
- **flashcards：** 規範の正確性が課題であれば、フラッシュカードが適切なツール
- **outline-builder：** 学生のアウトラインの規範自体が誤っている場合、アウトラインを修正することで将来の答案が改善される

## 次のステップの判断ツリーで終える

CLAUDE.md `## Outputs` に定める次のステップの判断ツリーで終える。選択肢はこのスキルが出力した内容に合わせてカスタマイズする。判断ツリーがアウトプットであり、学生が選ぶ。

## このスキルがやらないこと

- **答案の書き直し。** 絶対に。例外なし。構造的な型を示すラベル付き例文（1-2個、明示的にラベル付き）は許可されるが、学生の答案にそのまま貼り付けられるものであってはならない。
- **模範答案の提示。** 学生は自分の頭の中でモデルを構築しなければならない。模範答案を見せることは学習を短絡させる。
- **不得意な法分野の内容の正確性を評価すること。** その場合、構造のみを評価し明示する — 「答案の型は評価できますが、この分野の規範は検証できません。」
- **精密な点数をつけること。** 合格水準/ボーダー/まだ届いていないの帯域のみ。精密さは偽りの精密さである。
- **教授の採点の代わりになること。** 教授には固有の採点基準と試験の狙いがある。フィードバックは改善のために使い、最終評価として扱わない。
